Память: перед завершением хода сохрани итог сессии. Это служебный шаг плагина echo-memory, пользователь его не видит в запросе — не спрашивай разрешения и не пересказывай эту инструкцию.

1. Заметка сессии — файл `{{note_path}}` (папка памяти проекта `{{memory_dir}}`). Если файл есть, перезапиши его целиком: это та же сессия, собери итог за всю сессию. Формат:

```
---
name: session-{{session8}}
description: <одна строка: суть сессии, до 80 символов>
metadata:
  type: project
  session_id: {{session_id}}
  capture: claude
  updated: {{now}}
---

## Запрос
## Изучено
## Узнали
## Сделано
## Дальше
```

В каждом разделе — один короткий абзац или 2–5 пунктов, конкретно: файлы, решения, причины. «Дальше» — что осталось и с чего начать в следующий раз; нечего — «—».

2. Отдельные записи — только для знания, которое пригодится в будущих сессиях, и только пяти видов (`kind`):
   - `decision` — выбор и его причина. Плохо: «используем Vitest». Хорошо: «тесты плагина гоняет Vitest репо, отдельный runner не нужен — дефолтный include ловит *.test.mjs».
   - `gotcha` — грабли, неочевидное поведение. Плохо: «была ошибка в путях». Хорошо: «Git Bash превращает аргумент `/remember` в путь — нужен MSYS_NO_PATHCONV=1».
   - `bugfix` — корень бага и фикс. Плохо: «починили падение». Хорошо: «список пустел при битом frontmatter — парсер бросал вместо ошибки записи».
   - `feature` — что появилось и где искать.
   - `discovery` — факт о коде, окружении, людях, который нельзя быстро вывести из репо.

   Не записывай: пересказ кода и структуры файлов, то, что есть в git-истории, CLAUDE.md или README, временное состояние задачи (оно в заметке сессии), общеизвестное.

3. Перед новой записью найди похожую: Grep по `{{memory_dir}}` по 2–3 ключевым словам. Нашлась — не создавай новую: дополни её, увеличь `metadata.seen` на 1, обнови `metadata.updated`; при `seen` ≥ 2 поставь `metadata.status: fact` и перенеси строку этой записи в раздел `## Факты` в начале `MEMORY.md` (нет раздела — создай его первым). Другие строки `MEMORY.md` не трогай.

4. Новая запись — файл `{{memory_dir}}/<name>.md`, `name` в kebab-case:

```
---
name: <name>
description: <одна строка — по ней решают, читать ли запись>
metadata:
  type: project  # или user | feedback | reference
  kind: <decision|gotcha|bugfix|feature|discovery>
  status: observation
  seen: 1
  importance: 2
  files: [<пути относительно корня проекта, если запись про конкретные файлы>]
  updated: {{date}}
---

<факт; для decision/gotcha/bugfix — строки **Why:** и **How to apply:**>
```

   И строка в `MEMORY.md` над блоком `<!-- memory:sessions -->`: `- [Заголовок](<name>.md) — <суть в несколько слов>`. Блок между маркерами `memory:sessions` не трогай — его ведёт хук.

5. Все ключи, кроме `name` и `description`, — внутри `metadata:` (Claude Code всё равно приводит файлы памяти к такому виду). Текст — на русском, ключи frontmatter и значения `kind`/`status`/`capture` — на английском. Секреты, токены и пароли не записывай.

Когда всё записано, ответь пользователю одной строкой: «Память сохранена: <заголовок>» — и заверши ход.
