# 008 — Готовность к Kimi Code

## Зачем

Доступ к Claude может пропасть (политика регионов Anthropic с 12.11.2026). Переключение на Kimi Code CLI должно занимать минуты и не оставлять без инструментов. Сейчас **Claude остаётся основным агентом**: всё, что добавляет эта фича, работает рядом и не меняет поведение для Claude.

## Требования

- **FR-K01** Плагин `echo-memory` работает в Kimi Code: те же хуки (начало сессии, правки, конец хода), та же память `~/.claude/projects/<slug>/memory`, те же команды `remember`, `reflect`, `tidy`. Для Claude ничего не меняется.
- **FR-K02** Общие хуки из `~/.claude/hooks` (гварды, статус сессий) принимают данные Kimi и регистрируются в `~/.kimi-code/config.toml` одной командой синхронизации; повторный запуск не плодит дубли и не трогает чужие правила.
- **FR-K03** В Echo Studio есть выбор агента (Claude по умолчанию). Пути, CLI и форматы агента берутся из одного профиля, а не разбросаны по модулям.
- **FR-K04** Рабочее место запускает и продолжает сессии Kimi (`kimi`, `kimi -S <id>`) во вкладках, показывает их статус по тем же файлам состояния.
- **FR-K05** «Инструменты» показывают skills, агентов, MCP и плагины Kimi (`~/.kimi-code`, `~/.agents/skills`, проектные `.kimi-code/` и `.agents/`).
- **FR-K06** «Переписки» читают сессии Kimi (`session_index.jsonl`, `state.json`, `agents/*/wire.jsonl`) только на чтение.
- **FR-K07** Переключение — одно действие с понятным списком того, что произойдёт, и обратным ходом.

## Не цели

- Переносить сессии Claude в Kimi (у Kimi есть свой `/import-sessions`).
- Менять что-либо в конфиге Claude Code.
- Работать с Kimi как основным агентом до явного переключения.
