# ТЗ: раздел «Инструменты» с нуля — что установлено, чем пользуюсь, что убрать

> Сгенерировано /make-spec, 2026-10-28. Источник: «Переписать с нуля раздел „Инструменты“ Echo Studio: просто видеть установленные skills/plugins/commands/MCP/agents, сколько раз каждый использовался, находить заброшенные — что удалить, отключить, обновить. Текущий раздел перегружен и неудобен. Дальше — дизайн через /redesign-stand.»

## Цель

Вместо нынешнего экрана «Области → проект → итоговый набор» (`ToolsLayout.tsx` + `components/tooling/*`) сделать один простой экран, как `/skills`, `/plugins`, `/mcp` в Claude Code: единый список всего, что пользователь поставил сам, со счётчиком использования по транскриптам. На экране сразу видно, что заброшено, что можно обновить, и это можно выключить, удалить или обновить в один-два клика. Дизайн — через `/redesign-stand`, стенды серии 4NN.

## Требования

### 1. Что показываем

1.1. Вкладки по видам: **Skills, Plugins, Commands, MCP, Agents**, у каждой число элементов.

1.2. **Единый список, без «областей».** Левая панель со списком проектов и понятие «итоговый набор для проекта» удаляются. В списке:
- глобальное: `~/.claude/skills/*` (в т.ч. симлинки из `~/.agents/skills`), `~/.claude/commands/**/*.md` (подпапка = префикс `phase:`), `~/.claude/agents/*.md`, MCP из `~/.claude.json` → `mcpServers`, плагины из `~/.claude/plugins/installed_plugins.json`;
- проектное: `<project>/.claude/{skills,commands,agents}`, `<project>/.mcp.json` → `mcpServers`, `~/.claude.json` → `projects[<path>].mcpServers` (local-scope). Проекты — из `projects::all_projects`, worktree-папки `.claude/worktrees/*` не сканируются;
- плагинное: скиллы, команды, агенты и MCP установленных плагинов.

1.3. **Пометка источника** у каждой строки (как в Claude Code): «глобальный», «плагин <имя>», «проект <имя>» или «проекты · N».

1.4. **Копии склеиваются.** Проектные элементы одного вида с одинаковым именем — одна строка с пометкой «проекты · N». Пример: 10 speckit-скиллов в 17 проектах — это 10 строк «проекты · 17». Если такое же имя есть и глобально, это отдельная строка: у глобального свой путь и свои действия.

1.5. **Плагинное — в своих вкладках** с пометкой «плагин X». Удалить или обновить такую строку нельзя, вместо кнопок — ссылка-переход к плагину во вкладке Plugins. Строка плагина во вкладке Plugins показывает состав одной строкой («4 скилла · 1 команда · хуки») и суммарное использование частей.

1.6. **Встроенное в Claude Code не показываем**: встроенные скиллы (`simplify`, `code-review`, `update-config`, `init` и т.п.), встроенные агенты (`general-purpose`, `Explore`, `Plan`, `claude-code-guide`, `statusline-setup`) и встроенные слэш-команды (`clear`, `model`, `compact`, `mcp`, `plugin`, `exit`, `login`, `effort`, `reload-*` …). Критерий для скиллов и агентов: нет файла ни в одном из источников п. 1.2. Слэш-команды без файла в счётчики не идут.

1.7. **Поиск** — по имени и описанию внутри текущей вкладки.

1.8. **Фильтры**: «Все», «Заброшенные», «Есть обновление» (активен только после проверки, п. 4) и «Выключенные». Сочетаются с поиском.

1.9. **Сортировка**: по числу использований за доступную историю (по убыванию), при равенстве — по имени.

1.10. Как устроен верх экрана (вкладки + фильтры или сводка «что почистить» + вкладки), вид строки и карточки — решается на стенде (п. 7). Требования к данным и поведению от этого не зависят.

### 2. Использование

2.1. **Источник — только транскрипты** `~/.claude/projects/**/*.jsonl`, включая `subagents/*.jsonl` (см. память `usage-misses-subagents`). Своего журнала Echo не ведёт. Если Claude удалил транскрипт, его вызовы из счёта пропадают (решение пользователя).

2.2. **Что считаем «использованием»** (одна запись = +1, время — поле `timestamp` строки):
- **скилл**: `assistant` → `tool_use` с `name == "Skill"`, имя в `input.skill`. Ещё — `user`-строка с `<command-name>/имя</command-name>`, если такое имя есть среди скиллов. Префикс `plugin:` → плагинный скилл (`chisle:chisle-review`). Префикс с `/` (вид `Windows Apps/Sorter:speckit-tasks`) → проектный скилл, имя после последнего `:`;
- **команда**: `user`-строка с `<command-name>/имя</command-name>`, имя совпадает с файлом команды (глобальной, проектной или плагинной);
- **MCP**: `tool_use` с `name` вида `mcp__<server>__<tool>` → сервер `<server>`. Вид `mcp__plugin_<plugin>_<server>__…` → MCP плагина;
- **агент**: `tool_use` с `name` `Agent` или `Task`, тип в `input.subagent_type`. Префикс `plugin:` → агент плагина;
- **плагин**: сумма использований его частей.

2.3. **Привязка к проекту** — по slug папки транскрипта, по правилу из памяти `conversations-worktree-slug-cwd` (искать проект по slug пути, не по `cwd`). Для субагентов — slug родительской папки сессии.

2.4. **Производительность.** Сейчас это 4,2 ГБ и 1254 файла, проход на Node занимает 45 с.
- Разбор в Rust через `conversations::reader::jsonl_lines` в `spawn_blocking`. Строка сначала проверяется подстрокой (`"tool_use"` или `<command-name>`), JSON разбирается только у прошедших.
- Кеш агрегатов по файлу с ключом (путь, mtime, размер) — как `CACHE` в `workbench/usage.rs`. Кеш **сохраняется на диск** в `%LOCALAPPDATA%/<app id>/tools-usage-cache.json`. Записи исчезнувших файлов при чтении выбрасываются: это кеш, а не журнал, п. 2.1 не нарушает.
- Пока идёт первый проход, список инструментов показывается сразу, а на месте счётчиков стоит индикатор «считаю…».

2.5. **В строке**: число использований за всю доступную историю и дата последнего («сегодня», «3 дня назад», «12 сент.»). Не было ни разу — «не использовался».

2.6. **Начало истории** (самый ранний `timestamp` по всем транскриптам) — тихая подпись на экране: «История с 14 сент.».

2.7. **Что не измеряется.** Плагины без измеримых частей (только хуки, LSP вроде `rust-analyzer-lsp`, output styles) получают пометку «использование не считается». Заброшенными они не бывают.

### 3. Заброшенные

3.1. Элемент **заброшен**, если выполнены все три условия:
- последнее использование было больше 30 дней назад или его не было вовсе;
- установлен больше 30 дней назад;
- история (п. 2.6) охватывает не меньше 30 дней.

Если история короче 30 дней, фильтр «Заброшенные» неактивен с подсказкой «мало истории».

3.2. **Дата установки** берётся так:
- плагин — `installedAt` из `installed_plugins.json`;
- скилл из `npx skills` — `installedAt` из `~/.agents/.skill-lock.json`;
- файловый элемент — время создания файла (`SKILL.md` или `.md`);
- MCP — время создания файла, где он объявлен; для `~/.claude.json` это начало истории.

3.3. **Порог — 30 дней, константа**, в настройки не выносится.

3.4. Плагинная часть может быть заброшена при живом плагине. Её строка помечается, но действия остаются только у плагина (п. 1.5).

### 4. Обновления

4.1. **Проверка — только по кнопке** «Проверить обновления». Сама Echo в сеть не ходит. Результат держится в памяти до перезапуска Echo; время проверки подписано у кнопки.

4.2. **Плагины.** Echo выполняет `claude plugin marketplace update`, затем `claude plugin list --available --json`, и сравнивает установленную версию (а для плагинов с `gitCommitSha` — коммит) с доступной. Маркетплейсы с `source: directory` (у пользователя это `echo-studio` — плагин из репо) не проверяются.

4.3. **Скиллы из `npx skills`** (есть в `~/.agents/.skill-lock.json`).
- Записи группируются по `sourceUrl`.
- Для GitHub-источников Echo запрашивает `GET https://api.github.com/repos/<owner>/<repo>/contents/<родитель skillPath>`.
- У элемента-папки скилла берётся `sha` и сравнивается со `skillFolderHash`: не совпадает — значит есть обновление.

4.4. **Ошибки сети или лимита GitHub** (403/429) — заметка у кнопки «Не удалось проверить: <причина>». Метки обновлений, полученные до ошибки, сохраняются.

4.5. **Кому обновления недоступны:** самописным скиллам, командам и агентам, а также MCP. У них метки обновлений не бывает.

4.6. **Обновить**: плагин — `claude plugin update <name>@<marketplace>`, скилл — `npx -y skills update <name> -g`. Пока команда идёт, кнопка занята. После успеха — тост «Обновлено. Применится в новых сессиях Claude» и пересканирование. При ошибке — тост с последними строками stderr.

4.7. **«Обновить всё»** — кнопка при фильтре «Есть обновление». Элементы обновляются по очереди, итог одним тостом: «Обновлено N, ошибок M», ошибки раскрываются.

4.8. **Окружение дочерних процессов** — без переменных `CLAUDE*`, std-потоки null, по правилу `child_command` (память `child-stdio-null-stale-console`). Окна консоли не открываются.

### 5. Выключение

5.1. **Один глобальный переключатель** в строке и только там, где `tooling/write.rs` уже умеет писать глобальный ключ:
- скилл (в т.ч. проектный и плагинный) — `skillOverrides` в `~/.claude/settings.json`;
- плагин — `enabledPlugins`;
- глобальный MCP — `disabledMcpServers`.

У команд, агентов и чисто проектных MCP переключателя нет. Запись — существующим путём `set_enabled`, с копией и temp → rename.

5.2. **Проектные выключения, уже сделанные раньше** (`<project>/.claude/settings.local.json`, `~/.claude.json` → `projects[...]`), показываются в карточке строкой «выключен в: Booked, Trail». У каждого проекта кнопка «снять», которая пишет `enabled = true` в ту же область. Новых проектных выключений интерфейс не создаёт.

5.3. Фильтр «Выключенные» показывает элементы с глобальным выключением или хотя бы одним проектным.

### 6. Удаление и открытие

6.1. **Удаление всегда через `ConfirmDialog`.** В тексте — что именно и где будет удалено (пути или список проектов).

6.2. Что делает удаление по видам:

| Что | Как удаляется |
|---|---|
| Глобальный скилл из `npx skills` | `npx -y skills remove <name> -g` |
| Остальной глобальный скилл | папка → Корзина Windows |
| Глобальная команда или агент | файл → Корзина |
| Плагин | `claude plugin uninstall <name>@<marketplace>` |
| Глобальный MCP (user scope) | `claude mcp remove <name> -s user` |
| Проектные копии (п. 1.4) | в карточке список проектов с галочками (по умолчанию отмечены все) и кнопка «Удалить в N». Файлы и папки → Корзина. MCP из `.mcp.json` — запись из `mcpServers` (п. 6.3). MCP local-scope — `claude mcp remove <name> -s local` с `cwd` = папка проекта |
| Плагинные части | не удаляются (п. 1.5) |

6.3. **Правка `.mcp.json`:**
- копия → `%APPDATA%/<app id>/config-backups/<slug>/…` по общим правилам;
- файл перечитывается перед записью, удаляется один ключ из `mcpServers`, порядок остальных ключей и форматирование (отступ 2 пробела) сохраняются;
- запись через temp → rename;
- если `mcpServers` опустел, остаётся `{}`; файл не удаляется.

6.3a. **Копия перед CLI.** Перед каждой CLI-командой, меняющей конфиг (`claude plugin update/uninstall`, `claude mcp remove`, `npx skills update/remove`), — копия файлов, которые она может тронуть, в `config-backups` по общим правилам: `~/.claude.json`, `~/.claude/settings.json`, `~/.claude/plugins/installed_plugins.json`, `~/.agents/.skill-lock.json`. Причина — принцип I конституции: каждая запись с копией.

6.4. **Корзина** — через `SHFileOperationW`/`IFileOperation` с `FOF_ALLOWUNDO` или crate `trash`. Выбирает исполнитель: одна зависимость против своего FFI.

6.5. **Пути.** Удалять можно только пути внутри `~/.claude`, `~/.agents/skills` и `.claude/` известных проектов. Проверка — расширенный `tooling::paths::ensure_allowed`. Корень проекта и сам `.claude` удалить нельзя.

6.6. **После удаления** — пересканирование. Тост «Удалено»; для Корзины — «Удалено в Корзину».

6.7. **«Открыть»** в карточке:
- «Открыть в Zed» — файл `SKILL.md`, `.md` или конфиг с MCP (память `open-files-in-zed`);
- «Показать в Проводнике» — папка элемента.

Содержимое файла внутри Echo не показывается.

### 7. Карточка инструмента (по клику на строку)

7.1. **Шапка:** имя, вид, пометка источника, описание из front matter (`description`), путь или пути.

7.2. **Использование:**
- всего и последний запуск;
- мини-график по дням за доступную историю, столбики; пустые дни — нули;
- топ проектов по числу вызовов (до 5, остальное — «ещё N»).

7.3. **Действия по п. 4–6:** переключатель, «Обновить», «Удалить» (для копий — с выбором проектов), «Открыть в Zed», «Показать в Проводнике», плюс проектные выключения из п. 5.2.

7.4. **Плагин:** состав одной строкой и ссылки на его части в других вкладках. Отдельного списка частей со счётчиками нет.

### 8. Дизайн — `/redesign-stand`

8.1. Серия стендов **4NN** в `.planning/sketches/4NN-<компонент>/`, журнал — `.planning/TOOLS-STANDS.md` (новый). Добавить серию в паспорт стендов в `CLAUDE.md`.

8.2. **Части для стенда:**
- верх экрана (вкладки и фильтры против сводки «что почистить» и вкладок);
- строка списка (имя, пометка, счётчик, последний запуск, метки «заброшен» и «обновление», переключатель);
- карточка (п. 7);
- пустые состояния: нет элементов, «мало истории», «считаю…».

Вариантов с ошибками на стенде нет (память `stands-no-error-variants`).

8.3. **Данные стенда** — настоящие с этой машины. На 28.10:
- chrome-devtools — 18 897 вызовов;
- adversary — 429;
- redesign-stand — 157;
- cloudflare-скиллы — 0;
- speckit — «проекты · 17».

8.4. **Стиль** — язык Trail (`.planning/REDESIGN-TRAIL.md`), токены `src/styles/tokens.css`. Значки рельса и вкладки «Инструменты» не меняются.

### 9. Что удаляется из старого

9.1. **Фронтенд:**
- `src/components/tooling/*` (`ScopePanel`, `ToolList`, `ToolRow`, `ToolDetail`, `PluginDetail`, `McpDetail`, `ToolToggle`, `kinds.ts`);
- `src/components/layout/ToolsLayout.tsx` переписывается;
- `src/hooks/use-tooling.ts` — под новые команды;
- тесты на удалённое удаляются, на новое пишутся.

9.2. **IPC:**
- `list_tool_scopes` и `scan_tool_scope` заменяются одной командой списка (например, `list_tools`) и командой использования (`read_tool_usage`);
- `read_tool_file` удаляется, если после п. 6.7 не используется;
- `set_tool_enabled` и `list_config_backups` остаются;
- `list_tool_copies` переиспользуется или удаляется.

9.3. **Rust.** `tooling/scan.rs`, `effective.rs`, `copies.rs` чистятся от логики «итогового набора проекта», если она больше нигде не нужна. `frontmatter.rs`, `plugins.rs`, `mcp.rs`, `write.rs`, `paths.rs` и `watch.rs` переиспользуются. Отслеживание изменений (`useToolingWatch`) остаётся: после правки извне список обновляется сам.

### 10. Явно вне скоупа

- Свой журнал использования, переживающий чистку транскриптов.
- Показ встроенных инструментов Claude Code.
- Проектные переключатели (новые).
- Массовое удаление.
- Просмотр и правка содержимого файлов внутри Echo.
- Установка новых инструментов, маркетплейсы, поиск в каталоге.
- Хуки как отдельная вкладка (они видны только в составе плагина).
- Фоновая или автоматическая проверка обновлений.
- Порог «заброшенности» в настройках.

### 11. Инварианты CLAUDE.md — обновить

Раздел «Конфиг Claude Code — собственность пользователя» дополнить (только по действию пользователя, через `ConfirmDialog`):
- Echo удаляет файлы и папки инструментов в Корзину (п. 6.5);
- Echo удаляет записи из `mcpServers` в `.mcp.json` проектов с копией;
- Echo запускает `claude plugin update/uninstall`, `claude plugin marketplace update`, `claude mcp remove` и `npx skills update/remove`.

Общий `<project>/.claude/settings.json` по-прежнему не пишется.

## Критерии приёмки

- [ ] В разделе «Инструменты» нет левой панели проектов. Есть 5 вкладок со счётчиками, поиск и фильтры «Все / Заброшенные / Есть обновление / Выключенные».
- [ ] Каждый файл из `~/.claude/skills`, `~/.claude/commands`, `~/.claude/agents`, каждый плагин из `installed_plugins.json` и каждый MCP из `~/.claude.json` даёт ровно одну строку с пометкой «глобальный» или «плагин X».
- [ ] speckit-скиллы на этой машине — 10 строк с пометкой «проекты · 17» (число равно числу проектов, где есть папка). chrome-devtools из `.mcp.json` — одна строка «проекты · N».
- [ ] Встроенных скиллов, агентов и слэш-команд Claude Code в списке нет.
- [ ] Плагинные скиллы видны во вкладке Skills с пометкой «плагин X», без кнопок «Удалить» и «Обновить», со ссылкой на плагин.
- [ ] Счётчики совпадают с эталонным подсчётом по фикстуре. Rust-тест на фикстуре JSONL проверяет `Skill`, `<command-name>`, `mcp__…`, `mcp__plugin_…`, `Agent` и `Task`, префиксы `plugin:` и `путь:`, битую строку и строку из `subagents/`.
- [ ] Повторное открытие раздела после первого прохода отдаёт счётчики меньше чем за 1 с (кеш), в том числе после перезапуска Echo. Если транскрипт удалён, его вызовы исчезают из счёта.
