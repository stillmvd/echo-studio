# Feature Specification: Память Claude Code

**Feature Branch**: `004-memory`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "claude-mem стал платным и шумным — удалён. Нужна своя лёгкая память: забрать лучшие механики
у популярных инструментов (claude-mem, EchoVault, MemPalace, Basic Memory, claude-diary и др.), хранить в удобном
формате и управлять через Echo Studio." Разведка — `research.md`.

## Clarifications

### Session 2026-09-29

- Q: Своё с нуля или готовое? → A: Своё: готового под модель «итог пишет сам Claude, md, Windows, без БД и демона» нет; механики берём у лучших (см. research.md).
- Q: Как наполняется память? → A: Итог в конце значимой работы пишет сама основная сессия Claude по хуку Stop; стороннего LLM нет.
- Q: Где хранить? → A: Поверх встроенной auto memory: `~/.claude/projects/<проект>/memory/`, `MEMORY.md` — индекс, который Claude Code сам грузит на старте (первые 200 строк).
- Q: Как попадает в контекст? → A: Индекс заголовков на старте + полный текст через Read/Grep по требованию.
- Q: Когда Stop просит итог? → A: Первый Stop после значимой работы (были Edit/Write или ≥ 8 сообщений пользователя), дальше не чаще раза в 15 сообщений; заметка сессии перезаписывается.
- Q: Что в v1? → A: Всё: итог сессии, индекс, `/reflect`, наблюдение → факт, контекст при Read, страховка из JSONL, раздел памяти в Echo Studio.
- Q: Упаковка? → A: Плагин Claude Code в репо Echo Studio (`plugin/`), хуки на Node; ставится и выключается штатно через `/plugin` и вкладку Tools.
- Q: Что умеет Echo Studio? → A: Просмотр и поиск; правка и удаление; чистка и слияние. Импорт архива claude-mem не нужен (`~/claude-mem-archive` остаётся файлами).
- Q: Нужна ли копия с меткой времени, когда Echo Studio правит, переносит или сливает записи? → A: Да, как у конфига (принцип I конституции): перед каждой записью копия в `%APPDATA%/<app id>/memory-backups/<slug>/`, 20 на файл, тем же механизмом, что `config-backups`; удаление, как и было, уходит в `.archive/` с отменой.
- Q: Кто поднимает факты выше наблюдений в `MEMORY.md`, если хук правит только свой блок? → A: Тот, кто меняет статус: Claude по инструкции при `seen → 2` переносит строку записи в раздел `## Факты` в начале индекса, Echo Studio — при смене статуса или закреплении. Хук текст вне управляемого блока не трогает и не дублирует факты в своём выводе.
- Q: Чем закрепление отличается от факта? → A: Закреп сильнее: полный текст записей с `importance: 3` хук SessionStart кладёт в контекст каждой сессии проекта (бюджет 8 000 символов, лишние отрезаются целыми записями с предупреждением); факт — только строка в `## Факты` в начале `MEMORY.md`. Закрепление строку индекса не двигает. Действуют только в сессиях своего проекта (корень git: подпапки и worktree включены). Порядок силы: закреп > факт > наблюдение.
- Q: На каком языке пишутся заметки и записи? → A: На русском; ключи frontmatter и значения словарей (`kind`, `status`, `capture`) — на английском.
- Q: Где в Echo Studio раздел памяти? → A: Отдельный раздел рядом с Tools и Conversations; дубли — своя вкладка по всем проектам; форма выбирается на стенде.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Итог сессии пишется сам (Priority: P1)

Пользователь работает с Claude как обычно. Когда в сессии была значимая работа, перед остановкой Claude сам
записывает заметку сессии: что просили, что изучили, что узнали, что сделали, что дальше — и отдельные записи
для решений, граблей и фактов, которые стоит помнить. Пользователь ничего не вызывает.

**Why this priority**: без захвата памяти нет. Это замена автозахвата claude-mem без стороннего LLM и шума.

**Independent Test**: сессия с правкой файла → после ответа Claude в `memory/sessions/` появилась заметка
с `session_id` этой сессии и 5 разделами; сессия из одного вопроса без правок → заметки нет.

**Acceptance Scenarios**:

1. **Given** в сессии были Edit/Write, **When** Claude завершает ход впервые, **Then** хук Stop возвращает
   `decision:block` с инструкцией, Claude пишет заметку сессии и завершает ход; повторного блока нет.
2. **Given** заметка сессии уже есть и прошло 15 сообщений, **When** Stop, **Then** Claude перезаписывает ту же заметку.
3. **Given** короткая сессия без правок (< 8 сообщений), **When** Stop, **Then** хук молча пропускает.
4. **Given** в итоге есть строка вида `sk-…`, `ghp_…`, PEM или текст в `<private>`, **When** файл записан,
   **Then** секрет заменён на `[REDACTED]`.
5. **Given** хук упал с ошибкой, **When** Stop, **Then** сессия завершается как обычно (fail-open, `exit 0`).

---

### User Story 2 - Claude помнит на старте (Priority: P1)

При старте, `/clear`, resume и после компакции Claude получает короткий протокол работы с памятью и видит
индекс: устойчивые записи проекта и 3 последние сессии. Про прошлое он сначала ищет в памяти, а не угадывает.

**Why this priority**: запись без чтения бесполезна.

**Independent Test**: новая сессия в проекте с записями → в контексте есть протокол и блок последних сессий;
вопрос «что мы делали в прошлый раз» → Claude читает заметку сессии, а не гадает.

**Acceptance Scenarios**:

1. **Given** в `memory/sessions/` 10 заметок, **When** старт, **Then** в управляемом блоке `MEMORY.md` 3 последние
   (дата, заголовок, «дальше»), остальное содержимое `MEMORY.md` не тронуто.
2. **Given** вывод хука SessionStart, **Then** он ≤ 8 000 символов и обёрнут как справочные данные, не инструкции.
3. **Given** `MEMORY.md` длиннее 200 строк, **Then** хук предупреждает Claude сократить индекс.

---

### User Story 3 - Смотреть и править память в Echo Studio (Priority: P2)

Пользователь открывает раздел памяти: проекты со счётчиками, записи с видом, статусом и датой, фильтры,
полнотекстовый поиск. Открывает запись, правит текст и frontmatter, удаляет (в архив), переносит в другой проект.

**Why this priority**: удобное управление — причина делать своё, а не терпеть чужое.

**Independent Test**: список записей проекта совпадает с файлами в `memory/`; правка в приложении меняет файл,
индекс `MEMORY.md` остаётся согласованным.

**Acceptance Scenarios**:

1. **Given** папки auto memory, **When** открыт раздел, **Then** видны проекты, записи и заметки сессий отдельно.
2. **Given** запись, **When** удалена, **Then** она уходит в `memory/.archive/`, строка индекса убрана, есть «Отменить».
3. **Given** файл изменён снаружи, **Then** список обновляется (watch).

---

### User Story 4 - Чистка и слияние (Priority: P2)

Приложение находит похожие записи и предлагает слить: остаётся каноническая, теги объединяются, тексты
склеиваются с пометкой «Merged from», поглощённые получают `consolidated_into` и уходят в архив. Можно закрепить
запись (`importance: 3`) и пометить устаревшей (`valid_to`, `supersedes`).

**Independent Test**: две записи с похожими заголовками → в «Дубли» пара; слияние → одна запись, вторая в архиве
со ссылкой, индекс обновлён.

---

### User Story 5 - Наблюдение становится фактом (Priority: P3)

Новая запись рождается со `status: observation, seen: 1`. Когда Claude в новой сессии снова сталкивается с тем же
(находит запись поиском перед сохранением), он увеличивает `seen` вместо новой записи; при `seen ≥ 2` статус
становится `fact`, и Claude переносит строку записи в раздел `## Факты` в начале `MEMORY.md` — факты идут первыми.
Хук порядок строк вне своего блока не меняет.

---

### User Story 6 - Контекст при чтении файла (Priority: P3)

Когда Claude читает файл, упомянутый в поле `files:` записей, хук PreToolUse(Read) подмешивает заголовки этих
записей — один раз за сессию на файл, только если файл ≥ 1 500 байт и не менялся после последней записи о нём.

---

### User Story 7 - Страховка из транскрипта (Priority: P3)

Если значимая сессия закрыта без итога (Ctrl+C, `/exit`), SessionEnd пишет черновик заметки из JSONL: первый
запрос пользователя, последние реплики, тронутые файлы; `capture: extractive`. В следующей сессии протокол
предлагает Claude дописать черновик.

---

### User Story 8 - /reflect (Priority: P3)

Команда `/reflect` читает необработанные заметки сессий и текущий CLAUDE.md, ищет поправки пользователя,
повторившиеся ≥ 2 раз, и нарушения уже существующих правил; предлагает правки CLAUDE.md списком. Сам не пишет.
Обработанные заметки фиксируются в `memory/.reflect.log`.

### Edge Cases

- Сессия в папке без проекта (домашняя, Desktop) — пишем в папку auto memory этого cwd, как Claude Code.
- Несколько параллельных сессий одного проекта — у каждой своя заметка по `session_id`; блок индекса пересобирается из файлов.
- Битый frontmatter — запись показывается с ошибкой, остальное работает; хуки такую запись пропускают.
- Субагенты — Stop субагента (SubagentStop) итог не просит.
- Русский текст в поиске — поиск по подстроке без стемминга.

## Requirements *(mandatory)*

### Плагин

- **FR-001**: Плагин `plugin/` (manifest, `hooks/hooks.json`, скрипты `.mjs` на Node без зависимостей) ставится через `/plugin` из локального маркетплейса.
- **FR-002**: Хук Stop: блок с инструкцией итога, если (были Edit/Write или ≥ 8 сообщений пользователя) и (итог в этой сессии ещё не просили или с прошлого блока прошло ≥ 15 сообщений пользователя), либо в ходе была команда `/remember`; при `stop_hook_active` — пропуск; состояние в `%TEMP%/claude-memory/<session_id>.json`.
- **FR-003**: Инструкция итога: 5 разделов заметки сессии; отдельные записи только для decision/gotcha/bugfix/feature/discovery с примерами «плохо/хорошо» и списком «не писать»; перед новой записью — поиск по `memory/`, при совпадении `seen++`, при `seen ≥ 2` — `status: fact` и перенос строки в `## Факты`. Текст — на русском, ключи frontmatter и значения словарей — на английском.
- **FR-004**: SessionStart: протокол (≤ 5 строк) + пересборка управляемого блока `MEMORY.md` между маркерами `<!-- memory:sessions -->`; вывод ≤ 8 000 символов, урезание целыми записями.
- **FR-005**: PostToolUse(Write|Edit) по путям внутри `memory/`: secret scrub и вычистка служебных тегов на месте.
- **FR-006**: PreToolUse(Read): контекст записей по `files:` по правилам US6.
- **FR-007**: SessionEnd (≤ 1,5 с): extractive-черновик по US7, если значимая сессия без заметки.
- **FR-008**: Любая ошибка хука → `exit 0` без вывода, запись в `%TEMP%/claude-memory/errors.log`.
- **FR-009**: Команды `/remember` (записать сейчас) и `/reflect` (US8).

### Формат

- **FR-010**: Запись — один `.md` с frontmatter auto memory (`name`, `description`, `metadata.type`) плюс `kind`, `status` (observation|fact), `seen`, `importance` (1–3), `tags`, `files`, `supersedes`, `valid_to`, `consolidated_into`, `updated`.
- **FR-011**: Заметка сессии — `memory/sessions/YYYY-MM-DD_<session8>.md`, frontmatter `session_id`, `capture` (claude|extractive), `updated`, `title`.

### Echo Studio

- **FR-020**: Отдельный раздел памяти рядом с Tools и Conversations: проекты, записи, сессии, вкладка «Дубли» по всем проектам; фильтры по виду, статусу, дате; поиск по подстроке.
- **FR-021**: Правка текста и frontmatter, удаление в `.archive/` с отменой, перенос между проектами (только в проекты, у которых уже есть папка памяти); `MEMORY.md` синхронизируется.
- **FR-022**: Дубли: пары с похожестью заголовков ≥ 0.72, слияние по US4.
- **FR-023**: Закрепление (`importance`), устаревание (`valid_to`/`supersedes`), предупреждение о `MEMORY.md` > 200 строк. Смена статуса на `fact` переносит строку записи в `## Факты` в начале индекса. Закрепление (`importance: 3`) — полный текст записи в контексте каждой сессии проекта; раздел предупреждает, если закреплённые не влезают в бюджет SessionStart.
- **FR-024**: Запись файлов — по инвариантам проекта: копия перед записью в `%APPDATA%/<app id>/memory-backups/<slug>/<YYYYMMDD-HHMMSS>.md` (20 на файл, механизм `config-backups`), temp → rename, проверка пути (только внутри `~/.claude/projects/*/memory`).

### Key Entities

- **Запись** — устойчивое знание проекта (решение, грабли, факт).
- **Заметка сессии** — итог одной сессии, перезаписывается в её рамках.
- **Индекс** — `MEMORY.md`: строки записей + управляемый блок последних сессий.
- **Состояние хуков** — временный файл на сессию: счётчики, флаги, что уже подмешано.

## Success Criteria *(mandatory)*

- **SC-001**: В сессии с правками заметка сессии появляется в ≥ 95 % случаев без действий пользователя.
- **SC-002**: Короткие сессии без правок не создают записей.
- **SC-003**: Хуки добавляют < 200 мс к старту и Stop; нет резидентных процессов.
- **SC-004**: Вывод SessionStart ≤ 8 000 символов при любом объёме памяти.
- **SC-005**: Ни один секрет из тестового набора не доходит до файла.
- **SC-006**: Слияние двух записей в Echo Studio — ≤ 3 клика, индекс согласован.
