## User Scenarios & Testing *(mandatory)*

### User Story 1 - Сессия вне оболочки ведёт себя одинаково везде (Priority: P1)

Пользователь запустил Claude в Windows Terminal (проводник, `cc`) — в «Запущено» и в нижней полосе она видна. Клик по
ней в любом месте выводит вперёд окно терминала этой сессии. Если окно не нашлось — поповер объясняет, что сессия идёт в
терминале вне Echo, и предлагает, что можно сделать. Когда сессия завершилась — строка остаётся на время и предлагает
«Продолжить в Echo».

**Why this priority**: сейчас строка серая и не кликается, а в полосе кликается, но ничего не делает — пользователь не
понимает, что происходит.

**Independent Test**: запустить `claude` в Windows Terminal в папке Booked → в «Запущено» строка «вне оболочки» активна;
клик — окно WT выходит вперёд; закрыть WT → строка «завершена · вне оболочки», клик → «Продолжить в Echo» открывает
вкладку с этим разговором.

**Acceptance Scenarios**:

1. **Given** сессия запущена в Windows Terminal, **When** пользователь кликает её в «Запущено» или в полосе, **Then** окно
   этого терминала выходит на передний план (включая свёрнутое), Echo остаётся открытым.
2. **Given** сессия запущена во встроенном терминале VS Code, **When** клик, **Then** открывается вкладка терминала VS Code
   с этой сессией.
3. **Given** окно сессии не нашлось (процесс есть, окна нет), **When** клик, **Then** у строки появляется поповер «Сессия
   открыта в терминале вне Echo» с кратким объяснением и действиями: копировать id сессии, открыть папку проекта.
4. **Given** внешняя сессия завершилась не более часа назад и её папка — известный проект, **Then** она видна в
   «Запущено» как «завершена · вне оболочки», клик → «Продолжить в Echo» запускает продолжение этого разговора
   фоновой сессией в оболочке.
5. **Given** внешняя сессия идёт в корне `Projects` (не проект), **When** клик, **Then** окно выходит вперёд так же;
   «Продолжить в Echo» для неё не предлагается, подсказка объясняет почему.

### User Story 2 - Дерево показывает только проекты (Priority: P2)

Папки git-worktree (например `ProHouse\Smart Control-review`) не попадают в дерево. Любую папку можно скрыть из дерева
вручную из контекстного меню; скрытые видны в настройках со списком и кнопкой «Вернуть».

**Independent Test**: `Smart Control-review` отсутствует в дереве; скрыть `Breeze` из меню → пропадает; в Settings →
Рабочее место → «Скрытые проекты» — строка `Breeze` с «Вернуть» → проект снова в дереве.

**Acceptance Scenarios**:

1. **Given** в группе есть папка, чей `.git` — файл, **Then** её нет ни среди проектов, ни среди групп; остальное дерево
   без изменений.
2. **Given** проект скрыт вручную, **Then** его нет в дереве; его сессии, dev-сервер и процессы по-прежнему относятся к
   нему в «Запущено», полосе и процессах.
3. **Given** скрытый проект возвращён, **Then** он в дереве на своём месте без перезапуска.

### User Story 3 - Отключение от сессии понятно (Priority: P1)

Пользователь нажал Ctrl+C или `/exit` в терминале Claude. Вместо списка фоновых сессий Claude Code (agent view) ячейка
показывает «Отключено от сессии» с кнопками «Вернуться» и «Завершить сессию». Завершить сессию можно явно — в шапке
ячейки и из меню вкладки, с подтверждением. Крестик на вкладке только скрывает её, сессия продолжает работать —
подсказка говорит об этом.

**Independent Test**: в сессии набрать `/exit` → ячейка показывает «Отключено от сессии», «Вернуться» подключает обратно
к той же сессии; «Завершить сессию» → подтверждение → сессия пропадает из «Запущено». Ctrl+C во время ответа Claude
по-прежнему прерывает ответ.

**Acceptance Scenarios**:

1. **Given** в терминале введён `/exit`, Ctrl+Z или двойная «←» на пустом поле, **Then** в течение 1 с вместо agent view
   показано состояние «Отключено от сессии · Вернуться · Завершить сессию».
2. **Given** Claude печатает ответ, **When** Ctrl+C, **Then** ответ прерывается, подключение сохраняется.
3. **Given** вкладка сессии, **When** наведение на крестик, **Then** подсказка «Скрыть вкладку — сессия продолжит
   работать»; клик скрывает вкладку, сессия остаётся в «Запущено».
4. **Given** «Завершить сессию» в шапке ячейки или в меню вкладки, **Then** подтверждение с подписью; после подтверждения
   сессия остановлена, вкладка помечена завершённой с «Продолжить».

### User Story 4 - Элементы управления различимы (Priority: P2)

«Стоп» dev-сервера — заполненный квадрат цвета опасности с подсказкой; переключатель раскладки — единый сегментный
контрол с разделителями, отдельный от капсулы dev. Чип профиля chrome-devtools MCP — многоцветный значок Chrome.
Индикатор «watching» встроен в нижнюю полосу, плавающая таблетка убрана.

**Independent Test**: у проекта с работающим dev в шапке: «Стоп» — красный заполненный квадрат с подсказкой «Остановить
dev-сервер»; рядом сегмент 1×1 / 2×1 / 2×2 с разделителями; чип MCP — значок Chrome; справа внизу полосы — маленький
индикатор слежения с подсказкой, таблетки нет.

**Acceptance Scenarios**:

1. **Given** любое место, где квадрат значит «стоп» (dev в шапке, dev в пустом проекте, сессия в ячейке), **Then** квадрат
   заполнен цветом опасности, подсказка называет действие.
2. **Given** шапка проекта, **Then** переключатель раскладки — один сегментный контрол, визуально отделённый от капсулы
   dev; значок 1×1 не совпадает со «Стоп».
3. **Given** у проекта есть профиль chrome-devtools, **Then** чип показывает значок Chrome (оригинальные цвета), имя
   профиля и режим.
4. **Given** раздел «Рабочее место», **Then** индикатор слежения за конфигом — в правом краю нижней полосы, с подсказкой;
   плавающего элемента нет ни в одном разделе.

### User Story 5 - Чьи это процессы (Priority: P2)

В «Процессах» сессии из корня `Projects` — отдельная группа «Projects (корень)». Внутри любой группы процессы одной
сессии Claude собраны под строкой сессии (имя, статус): её claude, её MCP-серверы, её Chrome. «Без проекта» остаётся
только для того, что правда ни к чему не относится, с подсказкой, что это значит.

**Independent Test**: сессия пользователя в корне `Projects` с MCP — в группе «Projects (корень)» под строкой сессии
её claude.exe и node MCP; в группе «Echo Studio» фоновые сессии — каждая со своими процессами; «Без проекта» пусто
или только настоящие сироты.

**Acceptance Scenarios**:

1. **Given** процесс принадлежит живой сессии, **Then** он показан под строкой этой сессии внутри группы проекта.
2. **Given** сессия запущена в корне `Projects`, **Then** её процессы в группе «Projects (корень)».
3. **Given** «Без проекта» не пуст, **Then** у заголовка подсказка: что сюда попадает и почему это безопасно завершать.

### User Story 6 - Пустой проект не прыгает (Priority: P3)

Открыв проект без сессий, пользователь сразу видит кнопки и на месте списка «Продолжить» — силуэт списка, пока
разговоры грузятся. Пустое состояние (нет разговоров) показывается только после ответа; вёрстка не скачет.

**Acceptance Scenarios**:

1. **Given** разговоры проекта ещё не загружены, **Then** на месте списка — силуэты строк той же высоты.
2. **Given** ответ пришёл, **Then** список заменяет силуэты без сдвига кнопок; если разговоров нет — блок «Продолжить»
   исчезает, кнопки остаются на месте.

### User Story 7 - Вкладки можно перетаскивать (Priority: P2)

Вкладку Claude или лог dev можно перетащить в соседнюю ячейку, чтобы видеть dev и Claude рядом, и переставить внутри
ячейки. Зона сброса подсвечивается. Клавиатурная альтернатива — «Переместить в ячейку…» в контекстном меню вкладки.

**Independent Test**: раскладка 2×1, в первой ячейке вкладки «Claude» и «dev»; перетащить «dev» во вторую ячейку →
dev-лог справа, Claude слева, оба работают; перетащить обратно перед «Claude» → порядок изменился.

**Acceptance Scenarios**:

1. **Given** две ячейки, **When** вкладка перетаскивается над другой ячейкой, **Then** ячейка подсвечена как зона сброса;
   после сброса вкладка активна в ней, процессы не прерывались.
2. **Given** вкладка перетаскивается внутри своей ячейки, **Then** между капсулами виден указатель места; порядок
   меняется.
3. **Given** вкладка сброшена в пустую ячейку, **Then** ячейка занята проектом вкладки.
4. **Given** меню вкладки → «Переместить в ячейку…», **Then** перечислены ячейки раскладки; выбор переносит вкладку.

### User Story 8 - Раскладка у каждого проекта своя, пульт — режим (Priority: P1)

По умолчанию режим «Проект»: у проекта своя раскладка (1×1 / 2×1 / 2×2) и своё распределение вкладок по ячейкам,
которые запоминаются и восстанавливаются при переключении проекта. «Пульт» — отдельный режим с переключателем
«Проект / Пульт» на видном месте; значки раскладки в шапке проекта меняют только раскладку этого проекта и не уводят
в пульт. В пульте — поведение 005.

**Independent Test**: Smart Control: 2×1, dev слева, Claude справа; Echo Studio: 2×1, две сессии Claude; переключение
между проектами восстанавливает каждую раскладку; «Пульт» показывает общую сетку с авто-порядком; обратно «Проект» —
раскладки проектов на месте; после перезапуска всё сохранено.

**Acceptance Scenarios**:

1. **Given** режим «Проект», **When** выбрана раскладка 2×2, **Then** меняется только раскладка этого проекта, пульт не
   открывается.
2. **Given** у проекта A раскладка 2×1 с dev и Claude, у B — 1×1, **When** переключение A → B → A, **Then** у A снова 2×1 с
   теми же вкладками в тех же ячейках.
3. **Given** режим «Пульт», **Then** общая сетка, авто-порядок, булавки и «Вне сетки» работают как в 005.
4. **Given** новая сессия или dev запущены в режиме «Проект», **Then** вкладка появляется в фокусной ячейке проекта;
   свободная ячейка подсказывает, что в неё можно перетащить вкладку.

### User Story 9 - Контекстное меню по ПКМ (Priority: P2)

Правый клик по проекту в дереве, вкладке, капсуле dev, строке процесса и строке «Запущено» открывает меню в стиле
Kockers DS: появляется от точки клика, управляется клавиатурой (стрелки, Enter, Esc), закрывается кликом мимо. Пункты —
по смыслу, только полезное.

**Independent Test**: ПКМ по проекту → «Открыть», «Новая сессия Claude», «Запустить dev», «Открыть в проводнике»,
«Открыть в VS Code», «Копировать путь», «Скрыть из дерева»; стрелками выбрать «Копировать путь», Enter — путь в буфере;
Esc и клик мимо закрывают с анимацией.

**Acceptance Scenarios**:

1. **Given** ПКМ по элементу, **Then** меню появляется от точки клика с анимацией и исчезает с более короткой; не
   выходит за край окна.
2. **Given** меню открыто, **When** стрелки/Home/End, Enter, Esc, **Then** фокус ходит по пунктам, Enter выполняет, Esc
   закрывает и возвращает фокус.
3. **Given** меню открыто, **When** клик мимо, потеря фокуса окна или изменение размера, **Then** меню закрывается.
4. **Given** вкладка сессии, **Then** есть «Переместить в ячейку…», «Переподключить», «Завершить сессию», «Копировать
   id», «Скрыть вкладку»; dev-вкладка — «Открыть в браузере», «Перезапустить», «Остановить», «Копировать адрес»;
   процесс — «Завершить», «Копировать командную строку», «Открыть папку»; «Запущено» — «Перейти», «Завершить»
   (внешняя — «Показать окно», «Копировать id»).

---

### Edge Cases

- Окно внешней сессии есть, но `claude.exe` пережил закрытие вкладки WT (PseudoConsoleWindow без владельца) — поповер
  «окно не найдено», не ошибка.
- Внешняя сессия в VS Code, а расширение Claude Session Focus не установлено — поповер с подсказкой.
- Два attach на одну сессию, пользователь отсоединился в одной вкладке — состояние «Отключено» только у неё.
- Перетаскивание вкладки в ячейку, закреплённую булавкой в пульте — разрешено: ячейка переходит к проекту вкладки,
  булавка остаётся.
- Перетаскивание последней вкладки из ячейки — ячейка освобождается (режим «Проект»: показывает пустое состояние
  ячейки).
- Пользователь скрыл проект, у которого открыты вкладки — вкладки остаются, проект доступен через «Запущено» и полосу.
- Agent view открылся в сессии, которая в это время перешла в «ждёт тебя» — состояние «Отключено» показывает и
  статус, «Вернуться» ведёт в сессию.
- Процессы сессии, чья запись хука устарела (claudePid мёртв) — не под сессией, а «Без проекта» с причиной, как раньше.
- Контекстное меню на правом краю или внизу окна — сдвигается внутрь, точка анимации остаётся у курсора.
- Миграция сохранённого состояния 005 (раскладка, ячейки) — старые данные переезжают в пульт; у проектов раскладка по
  умолчанию 1×1, вкладки — в первой ячейке.

## Requirements *(mandatory)*

### Сессии вне оболочки

- **FR-101**: Внешняя сессия (терминал, VS Code) в «Запущено» и в полосе кликабельна; клик выводит окно её терминала на
  передний план; во встроенном терминале VS Code — открывает вкладку терминала.
- **FR-102**: Если окно не найдено — поповер у строки с объяснением и действиями (копировать id, открыть папку); без
  модального диалога и тостов.
- **FR-103**: Внешняя сессия, завершившаяся не более часа назад в известном проекте, видна как «завершена · вне
  оболочки» с действием «Продолжить в Echo» (продолжение того же разговора фоновой сессией).

### Дерево

- **FR-110**: Папка, чей `.git` — файл, в дерево не попадает.
- **FR-111**: «Скрыть из дерева» в контекстном меню проекта; список скрытых с «Вернуть» — в настройках; скрытие не
  влияет на принадлежность сессий, dev и процессов проекту.

### Терминал

- **FR-120**: Отсоединение от сессии и экран agent view распознаются не дольше чем за 1 с; вместо них — состояние
  «Отключено от сессии · Вернуться · Завершить сессию».
- **FR-121**: Ctrl+C без выделения по-прежнему прерывает ответ Claude.
- **FR-122**: «Завершить сессию» — в шапке ячейки с подписью и в меню вкладки, с подтверждением; крестик вкладки — скрыть
  вкладку с подсказкой.

### Элементы управления

- **FR-130**: Все кнопки «стоп» (dev в шапке, dev в пустом проекте, сессия) — заполненный квадрат цвета опасности с
  подсказкой-действием.
- **FR-131**: Переключатель раскладки — сегментный контрол с разделителями, отделён от капсулы dev.
- **FR-132**: Чип профиля chrome-devtools — многоцветный значок Chrome (встроенная графика, без сетевых загрузок).
- **FR-133**: Индикатор слежения за конфигом — в правом краю нижней полосы «Рабочего места»; плавающая таблетка
  удалена во всех разделах; слежение продолжает работать во всех разделах.
- **FR-134**: Список разговоров пустого проекта показывает силуэты до ответа; пустое состояние — только после ответа.

### Процессы

- **FR-140**: Процессы из корня `Projects` — группа «Projects (корень)».
- **FR-141**: Внутри группы процессы одной живой сессии Claude собраны под строкой сессии с её именем и статусом.
- **FR-142**: «Без проекта» — только процессы без проекта и без сессии; у заголовка подсказка.

### Вкладки и раскладка

- **FR-150**: Вкладки перетаскиваются между ячейками и внутри ячейки; зона сброса подсвечена; сброс в пустую ячейку
  занимает её проектом вкладки.
- **FR-151**: «Переместить в ячейку…» в меню вкладки — клавиатурная альтернатива.
- **FR-152**: Режим «Проект» (по умолчанию): раскладка и распределение вкладок по ячейкам хранятся на проект и
  восстанавливаются при переключении и после перезапуска.
- **FR-153**: Режим «Пульт» — отдельный, с переключателем «Проект / Пульт» в шапке правой панели; внутри — поведение
  005 (авто-порядок, булавки, «Вне сетки», Ctrl+Tab).
- **FR-154**: Значки раскладки в шапке проекта меняют раскладку только этого проекта.
- **FR-155**: Сохранённое состояние 005 мигрирует без потери открытых вкладок.

### Контекстное меню

- **FR-160**: Одно контекстное меню для всего приложения в стиле Kockers DS: анимация появления от точки клика, выход
  короче входа, клавиатура, закрытие по клику мимо, не выходит за край окна.
- **FR-161**: Пункты по местам: проект в дереве, вкладка сессии, вкладка dev, строка процесса, строка «Запущено»;
  опасные пункты последними под разделителем.

### Границы

- **FR-170**: Код Smart Control, AM 2.0 и Kockers DS не меняется; конфиг Claude Code и файлы проектов не пишутся.
- **FR-171**: Запуск и завершение процессов — только действием пользователя (принцип VII).

### Key Entities

- **Внешняя сессия**: сессия Claude не из оболочки; pid, окно терминала (если найдено), проект, время завершения.
- **Скрытый проект**: путь проекта, скрытого из дерева вручную.
- **Раскладка проекта**: раскладка (1×1 / 2×1 / 2×2), ячейки с упорядоченными вкладками и активной вкладкой, фокусная
  ячейка.
- **Режим рабочего места**: «Проект» или «Пульт».
- **Пункт меню**: подпись, значок, опасный ли, действие, подменю (для «Переместить в ячейку…»).

## Success Criteria *(mandatory)*

- **SC-101**: Клик по внешней сессии выводит её окно вперёд в 10 из 10 случаев для сессий из Windows Terminal; для
  сессий без окна поповер появляется не позже чем через 300 мс.
- **SC-102**: Ни одна worktree-папка из `Projects` не видна в дереве.
- **SC-103**: После `/exit`, Ctrl+Z или двойной «←» agent view виден не дольше 1 с; «Вернуться» возвращает к сессии в
  10 из 10 случаев; Ctrl+C прерывает ответ Claude.
- **SC-104**: Новичок отличает «Стоп» от раскладки без подсказки (проверка на скриншоте: разные формы и цвет).
- **SC-105**: В «Процессах» ни один процесс живой сессии не лежит вне строки своей сессии.
- **SC-106**: Открытие пустого проекта не сдвигает кнопки ни на один пиксель между появлением и ответом.
- **SC-107**: Перетаскивание вкладки между ячейками не прерывает ни сессию, ни dev-сервер; раскладки проектов
  восстанавливаются после перезапуска в 10 из 10 случаев.
- **SC-108**: Все проверки проекта зелёные: biome, typecheck, vitest, build, clippy, cargo test.

## Assumptions

- Окно внешней сессии ищется так же, как в моде Taskbar Claude Sessions: по `claudePid` → консольное окно → владелец
  окна; для VS Code — URI расширения Claude Session Focus (`vscode://stillmvd.claude-session-focus/focus?session=<id>`).
- Завершённые внешние сессии берутся из файлов состояния хука за последний час с мёртвым `claudePid`.
- Agent view распознаётся по тексту экрана attach-клиента; точные маркеры снимаются на живой сессии при реализации.
- Хранение скрытых проектов и раскладок — в сохранённом состоянии рабочего места Echo, не в конфиге Claude.
- Значок Chrome рисуется упрощённо (три сектора и центр) в фирменных цветах, без файлов Google.

## Решения (отклонения и уточнения при реализации)

- Внешняя сессия: Rust-команда `focus_session_window(pid)`: `AttachConsole(pid)` → `GetConsoleWindow` → `GA_ROOTOWNER`;
  если среди предков процесса есть `Code.exe` — открыть URI расширения; окно без владельца (осиротевший `claude.exe`)
  — «не найдено». Результат: `focused | vscode | not-found`. Завершённые внешние — `sessions::list` добавляет записи
  хука с `updatedAt` ≥ now − 1 ч, `claudePid` не жив, `projectDir` внутри известного проекта, статус `exited`,
  `kind: external`.
- Поповер — не `ConfirmDialog`: всплывашка у строки (якорь — строка/чип), закрывается кликом мимо и Esc, анимация как у
  меню.
- Worktree: сканер проверяет `dir.join(".git").is_file()` → папка пропускается целиком (ни проект, ни группа).
- Скрытые проекты: `hiddenProjects: string[]` в `workbench-store` (persist); фильтр в дереве; раздел «Рабочее место» в
  Settings со списком и «Вернуть».
- Agent view: детектор в `terminals.ts` — по данным attach (дебаунс 200 мс) ищет маркеры agent view в последних строках
  буфера; нашёл → `terminal_detach` и состояние `detached` с оверлеем. «Вернуться» = `reattach`. Выход attach по коду
  (terminal-exit) → то же состояние `detached` (вместо «Отсоединено · Подключить»).
- «Стоп»: lucide `Square` с `fill="currentColor"` и цветом `--color-danger`, класс `wb-stop`; 1×1 остаётся контурным
  внутри сегмента `.wl-seg` (фон, разделители `1px`, отступ от капсулы dev).
- Значок Chrome — `src/components/ui/ChromeIcon.tsx`, inline SVG 14 px.
- Процессы: Rust `Class.project_path` для cwd, равного корню `Projects`, = путь корня (правило `projects-root`);
  фронт группирует по `session` внутри группы, имя и статус — из `useClaudeSessions`; группа корня подписана
  «Projects (корень)»; `ProcessRow` получает `sessionName: string | null` для сессий, которых нет в списке
  (резерв).
- Скелетон: `EmptyProject` рисует 4 строки `.wb-rr.sk` высотой `ROW` пока `isPending` у запроса разговоров (и пока
  список проектов conversations не загружен).
- watching: `useToolingWatch` переезжает в `AppShell`; `StatusBar.tsx` удаляется; в `SessionStrip` справа — точка
  `.wb-watch` с `title`; хак с `marginRight` под таблетку удаляется.
- DnD — нативный HTML5 Drag and Drop (без зависимостей): `draggable` на капсуле, `dragover`/`drop` на ячейке и между
  капсулами; данные — `text/x-echo-tab` (`path`, `key`). В пульте сброс в ячейку другого проекта переназначает ячейку
  на проект вкладки (`manual: true`), вкладки прежнего проекта остаются в его списке.
- Режимы: `mode: 'project' | 'wall'` в сторе; `projectLayouts: Record<path, { layout, cells: { tabs: string[],
  active?: string }[], focus: number }>`; `tabs`/`activeTab`/`cells`/`layout` остаются для пульта. Миграция `version: 3`:
  открытые вкладки проекта → первая ячейка его раскладки. Переключатель «Проект / Пульт» — сегмент в шапке правой
  панели (`wb-ph`, слева от раскладки); в пульте шапка `wl-tb` как в 005 плюс тот же переключатель.
- Меню: `ContextMenu.tsx` переписывается по Kockers `t-menu` (карточка 20, пункты-капсулы 36, отступ 6, тень ring +
  pop); `transform-origin` в точке клика; вход 200 мс `translateY(-4px) scale(.96)`, выход 150 мс, скрытие в
  `onfinish`; подменю — вложенный список пунктов «→ Ячейка N». Rust: `open_in_vscode(path)` (`code <path>` через
  `child_command`), `reveal_in_explorer` уже есть. Копирование — буфер обмена webview.
- Ячейки в режиме «Проект»: пустая ячейка — «Свободная ячейка» с «+ Claude», «dev» (если есть) и подсказкой про
  перетаскивание.
- П. 12, замеры (T047). «До» живьём не снят — Echo пользователя в момент замера не был запущен; оценка по коду 005:
  хаб на каждую запись файла хука (дебаунс 0,5 с, пауза 1 с) запускал `claude agents --json` — при 8 занятых сессиях
  до 40–60 запусков в минуту, плюс запуск на каждый attach/stop/kill. «После» (bb6d9ed, 21.10, dev из `v2-integration`,
  4 занятых сессии из 7, Обзор открыт, 60 с, опрос 200 мс, запуски по родителю): 8 запусков `agents --json` в минуту от
  Echo, CPU `echo-studio.exe` 3,1 с за 60 с (≈ 5 % одного ядра при открытом Обзоре с процессами). Экземпляр
  пользователя из `main` с тем же кодом — 7 в минуту.
- «Без проекта · работает»: заголовок группы с подсказкой (`title` и значок «?»), как у «висящих», — там остаются
  сессии с `cwd` вне `Projects` (например домашняя папка) и их MCP.
- Детектор agent view: маркеры — короткие префиксы строк (`Quick safety check:`, `describe a task for a`, `enter to
  return ·`, `New sessions: `): в узкой ячейке 2×1 Claude переносит длинную строку вопроса о доверии, и полный маркер
  не совпадал — «Отключено» не появлялось (живая проверка 21.10). Якорь на начало строки остаётся — цитата маркеров
  в ответе Claude не срабатывает.
- Замечания пользователя после пачек 1–2 (21.10, через `projects-12`; задачи T051–T059):
  - A. Пробные сессии и dev в живых проверках убираются сразу после шага (`claude stop` + `rm`, dev — «Стоп»); чужие и
    старые сессии из «Продолжить» не возобновлять.
  - B. Статусы с понятными подписями и подсказками у всех: пустая сессия без первого запроса — «новая · ждёт задачу»
    (не «пауза»); «ответ готов» — ответ, который ещё не открывали, после просмотра — «ждёт задачу».
  - D. Экран пустого проекта — стандартные размеры: кнопки и шрифт как в шапке проекта, иконка меньше.
  - E. В ячейки пульта автоматически попадают только живые ждущие или работающие сессии, завершённые — никогда; лог
    dev — только открытый или закреплённый вручную.
  - F. Одно место для запущенного — «Запущено» над деревом, сгруппированное по проектам: строка проекта (иконка, имя,
    общий статус, жирным белым), под ней серыми — сессии (имя, статус) и dev (команда, порт); клик по проекту
    открывает проект, по сессии/dev — эту вкладку; корень — группа «Projects». Чипы активности из дерева убраны —
    дерево только для навигации.
  - G (вместо C — точки слежения в полосе). Внизу две отдельные пилюли: слева «Недавние» — последние 5–6 открытых
    сессий (история переходов, по ней же Ctrl+Tab; без «Вне сетки» и полного списка), справа — короткая пилюля
    watching, как прежняя плавающая.
  - H. Значки статусов — сплошные и крупные, в стиле зелёной галочки: заполненный круг одного размера с белым глифом,
    цвет по типу одной яркости, без стекла (работает, ждёт тебя, ответ готов, ждёт задачу, новая, вне Echo,
    завершена, dev работает/ошибка). Вариант выбирает пользователь на стенде (2–3 варианта).
- Узкая ячейка (`.wl-cell` — container, ≤ 560 px): «Завершить сессию» — только значок с подсказкой, у вкладок
  минимальная ширина 72 px (без этого подписи вкладок схлопывались до нуля).
