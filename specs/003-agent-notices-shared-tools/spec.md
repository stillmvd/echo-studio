# Feature Specification: Уведомления агентов и одинаковые инструменты

**Feature Branch**: `003-agent-notices-shared-tools`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "v0.4.0 (фича 003) — уведомления агентов и одинаковые инструменты. 1) Conversations:
отчёт фонового агента показывать шагом ленты, а не «You». 2) Tools, область проекта: свои сверху, глобальные в
свёрнутой группе «Inherited from Global · N», без «Project only». 3) Одноимённые инструменты по реальным
правилам приоритета Claude Code: проигравший «Overridden by …», победитель «Overrides …», чип «N overridden».
4) Копии в других проектах: тихий признак «also in N projects», в деталях «Also found in» с Same/Differs.
Только чтение. Решение совета агентов 2026-09-26."

## Clarifications

### Session 2026-09-26

- Q: Как показывать одинаковые инструменты? → A: Решено советом (практик, визуал, нативная понятность,
  модератор) и сверено с документацией Claude Code: конфликт имён решается приоритетом, поэтому показывается
  «кто кого перекрывает»; копии в других проектах — нейтральная справка, не предупреждение.
- Q: Считать ли skill плагина и свой skill с тем же именем конфликтом (как в v0.3.1)? → A: Нет. Skills
  плагина живут в своём пространстве имён (`/плагин:имя`) и грузятся вместе со своими; они показываются в
  «Also found in», а не как перекрытие. Заменяет FR-005 фичи 002.
- Q: Нужны ли просмотр разницы файлов и отдельный экран общих инструментов? → A: Отложены; Same/Differs,
  дата и открытие папки закрывают сценарий.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Видно, какая версия инструмента сработает (Priority: P1)

В проекте лежит своя копия skill или команды, а в глобальной папке — одноимённая. Claude Code запустит
глобальную, проектная молчит. Пользователь видит это в списке: проигравшая строка зачёркнута с подписью, кто
её перекрывает, у победившей — кого она перекрывает. В шапке — чип «N overridden», клик оставляет в списке
только участников перекрытий.

**Why this priority**: сейчас пользователь думает, что работает проектная копия, а она не работает —
это ошибка, которую трудно заметить иначе.

**Independent Test**: положить skill `x` в `~/.claude/skills` и в `.claude/skills` проекта; в области проекта
проектный `x` зачёркнут с «Overridden by global», глобальный — «Overrides project»; чип «2 overridden»,
фильтр по клику показывает эти две строки.

**Acceptance Scenarios**:

1. **Given** skill с одним именем глобально и в проекте, **When** открыта область проекта, **Then** проектный
   помечен «Overridden by global» и зачёркнут, глобальный помечен «Overrides project».
2. **Given** skill и команда с одним именем, **When** открыта область, **Then** команда помечена «Overridden
   by skill», skill — «Overrides command».
3. **Given** агент с одним именем глобально и в проекте, **When** открыта область проекта, **Then** глобальный
   помечен «Overridden by project».
4. **Given** MCP-сервер с одним именем в local и user, **When** открыта область проекта, **Then** user-запись
   помечена «Overridden by local».
   Агенты и MCP плагинов в перекрытиях не участвуют.
5. **Given** skill плагина и свой skill с тем же коротким именем, **When** открыта область, **Then** ни один
   не помечен перекрытием.
6. **Given** в области есть перекрытия, **When** пользователь нажимает чип «N overridden», **Then** в списке
   только участники перекрытий; повторный клик возвращает полный список; без перекрытий чипа нет.

### User Story 2 - Свои инструменты проекта не тонут в глобальных (Priority: P1)

В области проекта 5–10 своих инструментов и 133 глобальных. Пользователь видит свои сверху, а глобальные —
одной свёрнутой группой «Inherited from Global · N», которая читается как действующая в проекте, а не как
выключенная.

**Why this priority**: сейчас свои приходится искать или включать фильтр; группа решает это без фильтра.

**Independent Test**: открыть проект с 5 своими skills; первые строки — свои, ниже свёрнутая группа с
числом глобальных; раскрытие показывает глобальные обычными строками; переключателя «Project only» нет.

**Acceptance Scenarios**:

1. **Given** область проекта, **When** она открыта, **Then** инструменты проекта (project и local) стоят
   выше группы «Inherited from Global · N», где N — число показанных глобальных элементов.
2. **Given** группа, **When** пользователь нажимает на заголовок, **Then** она раскрывается/сворачивается;
   состояние сохраняется при переключении областей и перезапуске; по умолчанию свёрнута.
3. **Given** введён поиск, **When** совпадения есть в свёрнутой группе, **Then** они видны без ручного
   раскрытия.
4. **Given** у проекта нет своих инструментов выбранного типа, **When** он открыт, **Then** группа
   раскрыта автоматически.
5. **Given** тип Skills, **When** группа раскрыта, **Then** внутри неё действуют группы skills по
   вендору, как в области Global.

### User Story 3 - Где ещё лежит копия и отличается ли (Priority: P2)

Команда `redesign-stand` есть в четырёх проектах, все версии разные. У проектной строки тихо написано
«also in 3 projects». В деталях — секция «Also found in»: Global, проекты и плагины с тем же именем, у
каждого «Same» или «Differs», у отличающихся — дата изменения, кнопка открывает папку файла в Проводнике.

**Why this priority**: помогает решить, что вынести в плагин и какую копию взять за основу, но на работу
текущего проекта не влияет.

**Independent Test**: в двух известных проектах команда `a` с разным текстом, в третьем — с одинаковым; у
строки первого «also in 2 projects»; в деталях один «Same», один «Differs» с датой; кнопка открывает папку.

**Acceptance Scenarios**:

1. **Given** проектный инструмент, у которого в других известных проектах есть одноимённый того же типа,
   **When** открыта область, **Then** строка показывает нейтральную пометку «also in N projects».
2. **Given** любой инструмент-файл (skill, command, agent), **When** открыты детали, **Then** секция «Also
   found in» перечисляет другие места с тем же именем и типом — Global, проекты, плагины; текущая область
   не перечисляется; при отсутствии мест секции нет.
3. **Given** место в списке, **When** его содержимое совпадает с текущим, **Then** оно помечено «Same»;
   иначе — «Differs» и дата изменения его файла.
4. **Given** больше 6 мест, **When** секция показана, **Then** видны первые 6 и «N more», раскрывающее
   остальные.
5. **Given** место в списке, **When** пользователь нажимает «Show in folder», **Then** открывается папка
   его файла в Проводнике; файлы не копируются и не меняются.

### User Story 4 - Отчёт фонового агента не выдаётся за мою реплику (Priority: P2)

Фоновый агент закончил работу, Claude Code записал его отчёт в лог как сообщение пользователя, и лента
подписывает его «You». Пользователь видит вместо этого шаг «Agent "<описание>" finished · <статус>», а
отчёт — свёрнутым текстом, который можно раскрыть.

**Why this priority**: путаница, кто что написал, при перечитывании сессии; встречается в каждой сессии с
фоновыми агентами.

**Independent Test**: открыть сессию `7c2e3786` проекта Unmasking_Julia; уведомления показаны шагами с
описанием агента и статусом, «You» у них нет; отчёт раскрывается и читается как отформатированный текст.

**Acceptance Scenarios**:

1. **Given** сообщение с признаком уведомления агента, **When** сессия открыта, **Then** оно показано шагом
   ленты с описанием из уведомления и статусом, без подписи «You».
2. **Given** старый лог без признака, **When** текст сообщения начинается с разметки уведомления,
   **Then** оно показано так же.
3. **Given** шаг уведомления, **When** пользователь раскрывает его, **Then** отчёт агента показан как
   отформатированный текст; по умолчанию свёрнут.
4. **Given** статус «failed», «killed» или «stopped», **When** шаг показан, **Then** статус заметно
   отличается от «completed».
5. **Given** экспорт сессии в markdown, **When** в ней есть уведомления, **Then** они выгружаются как
   отчёт агента, а не как реплика пользователя.

---

### Edge Cases

- Победитель перекрытия выключен пользователем — он не загружается, поэтому перекрытия нет: пометки не
  ставятся, чип его не считает.
- Три места с одним именем (global skill, project skill, project command) — победитель один (global skill),
  остальные два «Overridden by …» каждый со своим победителем.
- В области Global одноимённые элементы глобальных skills и команд — правило «skill побеждает команду»
  действует и там.
- Уведомление без `<summary>` — шаг «Agent finished · <status>»; без `<result>` — нечего раскрывать.
- Разметка уведомления битая — сообщение показывается как раньше, текстом, лента не ломается.
- Место в «Also found in» — плагин: показывается имя плагина; Same/Differs считается так же.
- Проект пропал (missing) — в «Also found in» и в счёт «also in N projects» не входит.
- Файл места не читается — место показано с пометкой «unreadable» вместо Same/Differs.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Для одноимённых skills и команд одного типа имени приложение MUST определять победителя по
  приоритету Claude Code: global выше project; любой skill выше любой команды; skills и команды плагинов в
  перекрытиях не участвуют.
- **FR-002**: Для агентов MUST действовать приоритет project выше global; для MCP — local выше project выше
  global. Элементы плагинов в перекрытиях не участвуют.
- **FR-003**: Проигравший MUST показываться с пометкой «Overridden by global|project|local|skill»;
  победитель — «Overrides …» с перечнем проигравших источников.
- **FR-004**: Выключенный элемент MUST NOT участвовать в перекрытии.
- **FR-005**: Шапка списка MUST показывать чип «N overridden» (N — участники перекрытий), клик включает и
  выключает фильтр; чип «N duplicates» и пометка «same name» удаляются.
- **FR-006**: В области проекта инструменты проекта MUST стоять выше свёрнутой по умолчанию группы
  «Inherited from Global · N»; состояние группы MUST сохраняться между областями и перезапусками.
- **FR-007**: Группа MUST раскрываться автоматически при совпадениях поиска внутри неё и когда своих
  элементов выбранного типа нет.
- **FR-008**: Переключатель «Project only» MUST быть удалён.
- **FR-009**: Проектный инструмент-файл с одноимённым инструментом того же типа в других известных живых
  проектах MUST показывать нейтральную пометку «also in N projects».
- **FR-010**: Детали инструмента-файла MUST показывать секцию «Also found in»: места с тем же именем и типом
  (Global, проекты, плагины), кроме текущей области; «Same»/«Differs» по содержимому файла; у «Differs» —
  дата изменения; первые 6 и «N more».
- **FR-011**: Каждое место MUST иметь действие «Show in folder», открывающее папку файла; приложение MUST NOT
  создавать, копировать или менять файлы инструментов.
- **FR-012**: Сообщение пользователя с признаком уведомления агента (поле происхождения, либо, при его
  отсутствии, текст, начинающийся с разметки уведомления) MUST показываться шагом ленты «Agent "<summary>"
  finished · <status>» без подписи «You».
- **FR-013**: Отчёт агента MUST показываться свёрнутым форматированным текстом с раскрытием по клику.
- **FR-014**: Статусы кроме «completed» MUST визуально отличаться от «completed».
- **FR-015**: Экспорт сессии MUST выгружать уведомление как отчёт агента, не как реплику пользователя.
- **FR-016**: Уведомление, чья разметка не разбирается, MUST показываться как раньше — текстом.
- **FR-017**: Форма шага уведомления, пометок перекрытия, пометки «also in N projects», секции «Also found
  in» и группы «Inherited from Global» MUST выбираться на стенде до реализации.

### Key Entities

- **Перекрытие**: имя, тип; победитель (источник) и проигравшие (источники).
- **Место копии**: область (Global, проект, плагин), путь файла, Same/Differs, дата изменения.
- **Уведомление агента**: описание (summary), статус, отчёт (result), время.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На машине пользователя каждая проектная копия, которую перекрывает глобальная, помечена;
  число в чипе совпадает с числом строк под фильтром.
- **SC-002**: В области проекта со 133 глобальными skills свои видны на первом экране без прокрутки и без
  фильтра.
- **SC-003**: Для `redesign-stand` в Echo Studio секция «Also found in» перечисляет 3 других проекта с
  верными Same/Differs.
- **SC-004**: В сессии `7c2e3786` ни одно уведомление агента не подписано «You».
- **SC-005**: Ни одно действие фичи не меняет файлы инструментов и конфиг Claude Code.

## Assumptions

- Enterprise (managed) инструменты и вложенные `.claude/skills` подпапок приложение не сканирует — в
  приоритете не участвуют.
- «Global» — `~/.claude` пользователя; «known projects» — проекты из списка областей Tools.
- Сравнение «Same/Differs» — по содержимому файла побайтно (для skill — файл `SKILL.md`); сравнение
  регистронезависимо по имени.
- Дата изменения — время изменения файла в системе.
- Статусы уведомления: completed, failed, killed, stopped, running; прочие показываются как есть.
- Пометка «also in N projects» — только у проектных элементов; секция «Also found in» — у любых
  инструментов-файлов (skill, command, agent), у плагинов и MCP её нет.
- Отложено: просмотр разницы файлов, отдельный экран общих инструментов, перенос/синхронизация копий.
