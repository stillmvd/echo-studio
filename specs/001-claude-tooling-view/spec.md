# Feature Specification: Обзор инструментов Claude

**Feature Branch**: `001-claude-tooling-view`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "Вкладка вместо Memories: установленные для Claude Code skills, plugins, MCP-серверы, commands и agents — глобальные, проектные и из плагинов. Просмотр и включение/выключение plugins, MCP и skills. EchoVault из приложения вырезать."

## Clarifications

### Session 2026-09-26

- Q: Куда писать выключение для проекта? → A: Только в личный `.claude/settings.local.json` проекта; общий `.claude/settings.json` приложение не меняет.
- Q: Что делать, если у Claude Code нет штатного выключателя skill? → A: Только просмотр: переключателя нет, причина в подсказке; файлы skills приложение не трогает.
- Q: Где хранить копии файлов настроек и сколько? → A: В папке данных Echo Studio (AppData), последние 20 копий на каждый файл; список и Show in Explorer — в Settings.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Что у меня установлено глобально (Priority: P1)

Пользователь открывает вкладку инструментов и сразу видит всё, что установлено для Claude Code на уровне
пользователя: skills, plugins, MCP-серверы, commands и agents. Может отфильтровать по типу, найти по имени
или описанию, открыть элемент и прочитать его описание и содержимое, показать файл в проводнике.

**Why this priority**: это ядро фичи — сейчас у пользователя 105 skills, 39 agents, 13 commands и плагины,
и нигде нельзя увидеть их вместе. Без этого остальные истории не имеют смысла.

**Independent Test**: открыть вкладку на машине с настроенным Claude Code и сверить список с содержимым
папок конфигурации: каждый skill, command, agent, plugin и глобальный MCP-сервер найден, у каждого видны
имя, тип и описание.

**Acceptance Scenarios**:

1. **Given** в конфигурации пользователя есть skills, commands, agents, plugins и MCP-серверы, **When** он
   открывает вкладку, **Then** видит область «Global» со счётчиками по каждому типу и списком элементов.
2. **Given** открыта область, **When** пользователь выбирает тип «MCP», **Then** в списке остаются только
   MCP-серверы, счётчик совпадает с числом строк.
3. **Given** список, **When** пользователь вводит часть имени или описания, **Then** остаются совпадения
   с подсветкой найденного.
4. **Given** выбран skill, **When** пользователь открывает его, **Then** видит имя, описание, путь,
   источник (свой / из плагина) и содержимое основного файла в читаемом виде.
5. **Given** выбран MCP-сервер, **When** пользователь открывает его, **Then** видит способ подключения
   (команда с аргументами или адрес), а значения переменных окружения и заголовков скрыты, пока их
   явно не показать.

---

### User Story 2 - Что видит Claude в конкретном проекте (Priority: P2)

Пользователь выбирает проект из списка слева (те же проекты, что в Conversations) и видит итог: всё, что
Claude Code получит в этом проекте — глобальное, проектное и принесённое включёнными плагинами. У каждого
элемента помечено, откуда он пришёл и не перекрыт ли он другим с тем же именем.

**Why this priority**: главный вопрос при работе с проектом — «почему Claude здесь видит (или не видит)
этот инструмент». Отвечает на него только собранный итог.

**Independent Test**: для проекта с собственными skills и `.mcp.json` открыть его область и убедиться,
что проектные элементы помечены как проектные, глобальные — как глобальные, а элемент с совпадающим
именем показан как перекрывающий или перекрытый.

**Acceptance Scenarios**:

1. **Given** у проекта есть свои skills и MCP-серверы, **When** пользователь выбирает проект, **Then**
   видит их вместе с глобальными и плагинными, у каждого — метка источника.
2. **Given** проектный и глобальный skill с одинаковым именем, **When** пользователь смотрит итог,
   **Then** видно, какой из них действует, а какой перекрыт.
3. **Given** итог проекта, **When** пользователь включает показ «только проектное», **Then** видит лишь
   то, что лежит в самом проекте.
4. **Given** в проекте нет своей конфигурации, **When** он выбран, **Then** итог состоит из глобального
   и плагинного, а пустота проектной части показана явно.

---

### User Story 3 - Включить или выключить (Priority: P3)

Пользователь выключает плагин, MCP-сервер или skill (глобально или для проекта) и включает обратно, не
открывая файлы конфигурации руками. Перед изменением сохраняется копия файла, изменение касается только
этого переключателя.

**Why this priority**: полезно, но только поверх работающего обзора; единственная часть фичи, которая
пишет в конфигурацию Claude.

**Independent Test**: выключить плагин, убедиться, что в файле настроек изменилась только его запись, что
рядом появилась копия прежнего файла, и что новая сессия Claude Code плагин не загружает; включить обратно.

**Acceptance Scenarios**:

1. **Given** включённый плагин, **When** пользователь выключает его, **Then** плагин помечен
   выключенным, его skills, commands и agents в итогах помечены недоступными, копия файла настроек
   сохранена.
2. **Given** глобальный MCP-сервер, **When** пользователь выключает его только для проекта, **Then**
   сервер выключен в этом проекте и остаётся включённым в остальных; изменение записано в личные
   настройки проекта, общий файл настроек проекта не изменился.
3. **Given** файл настроек изменён снаружи после того, как приложение его прочитало, **When**
   пользователь нажимает переключатель, **Then** приложение перечитывает файл и применяет изменение
   к свежей версии, не затирая чужие правки.
4. **Given** запись не удалась (файл занят, нет прав), **When** пользователь переключает, **Then**
   переключатель возвращается в прежнее положение, показана понятная ошибка, файл не повреждён.
5. **Given** тип элемента нельзя выключить штатными средствами Claude Code, **When** пользователь
   смотрит элемент, **Then** переключателя нет, а причина видна в подсказке.

---

### User Story 4 - Приложение без EchoVault (Priority: P1)

Пользователь, у которого EchoVault не установлен, запускает приложение и не видит ничего, связанного с
EchoVault: нет вкладки Memories, нет ошибок «EchoVault not initialized», нет секций EchoVault и Backups в
Settings, в статус-капсуле нет числа memories и кнопки Reindex.

**Why this priority**: сейчас каждая вкладка Memories и Settings показывает ошибку про отсутствующий
EchoVault; новая вкладка встаёт на место Memories. Делается первым.

**Independent Test**: запустить приложение на машине без `~/.memory` — ни одного упоминания EchoVault
в интерфейсе, ни одной ошибки в консоли, приложение не создаёт `~/.memory`.

**Acceptance Scenarios**:

1. **Given** приложение запущено, **When** пользователь смотрит рейл, **Then** видит вкладку инструментов,
   Conversations и Settings; вкладки Memories нет.
2. **Given** Settings, **When** пользователь открывает его, **Then** видит пути конфигурации Claude и
   Conversations, но не EchoVault и не резервные копии index.db.
3. **Given** приложение работает, **When** пользователь смотрит статус-капсулу, **Then** она сообщает о
   слежении за конфигурацией Claude без упоминания memories и Reindex.

---

### User Story 5 - Список обновляется сам (Priority: P3)

Пользователь ставит skill, меняет `.mcp.json` или включает плагин в Claude Code — открытая вкладка
обновляется без перезапуска и без кнопки.

**Why this priority**: удобство; без него обзор быстро устаревает, но фича полезна и без этого.

**Independent Test**: при открытой вкладке создать папку skill с описанием в глобальной папке skills —
элемент появляется в списке в течение пары секунд.

**Acceptance Scenarios**:

1. **Given** открыта вкладка, **When** в папке skills появляется новый skill, **Then** он появляется в
   списке без действий пользователя.
2. **Given** открыт элемент, **When** его файл удалён снаружи, **Then** элемент исчезает из списка, а
   панель деталей сообщает, что он удалён.

---

### Edge Cases

- Файл с описанием skill или agent без заголовочного блока или с битым блоком — элемент показан с
  пометкой ошибки и именем по папке/файлу; остальной список загружается.
- Битый JSON в файле настроек или `.mcp.json` — область показывает ошибку чтения этого файла, остальные
  источники читаются; переключатели для этого файла недоступны.
- Проект из Conversations, папки которого больше нет на диске — проект показан как недоступный, без
  попыток чтения.
- Плагин включён в настройках, но не найден в кэше плагинов — показан как «не установлен».
- Два плагина приносят skill с одинаковым именем — оба видны, у каждого своё пространство имён плагина.
- Очень длинные описания и файлы — детали прокручиваются, список не растягивается.
- Секреты: значения `env` и заголовков MCP-серверов скрыты по умолчанию.
- Ни одного элемента данного типа — у типа счётчик 0 и спокойный пустой вид, не ошибка.
- Одновременная запись Claude Code и приложения в один файл — приложение не теряет чужие правки
  (перечитать перед записью, атомарная замена).

## Requirements *(mandatory)*

### Functional Requirements

**Обзор**

- **FR-001**: Система MUST находить skills, commands, agents, plugins и MCP-серверы на уровне
  пользователя Claude Code.
- **FR-002**: Система MUST находить проектные skills, commands, agents и MCP-серверы для каждого
  проекта из Conversations и из списка проектов Claude Code.
- **FR-003**: Система MUST находить skills, commands, agents и MCP-серверы, которые приносят
  установленные плагины, и связывать их с плагином-источником.
- **FR-004**: Для каждого элемента система MUST показывать тип, имя, описание (если есть), область
  (global / проект / плагин), путь к файлу и состояние (включён / выключен / перекрыт / ошибка чтения).
- **FR-005**: Пользователь MUST иметь возможность выбрать область (Global или проект) и фильтровать
  элементы по типу; у каждого типа виден счётчик.
- **FR-006**: Пользователь MUST иметь возможность искать по имени и описанию в выбранной области.
- **FR-007**: Пользователь MUST иметь возможность открыть элемент и прочитать его содержимое в
  отформатированном виде (markdown для skills, commands, agents; параметры подключения для MCP;
  состав и версия для плагина).
- **FR-008**: Пользователь MUST иметь возможность показать файл элемента в проводнике.
- **FR-009**: Для проекта система MUST показывать итог «что видит Claude»: глобальное + проектное +
  из включённых плагинов, с меткой источника. Перекрытие показывается там, где правило Claude Code известно
  (проектный agent перекрывает пользовательский); для skills и commands с одинаковым именем в разных областях
  оба помечаются «совпадение имён».
- **FR-010**: Секретные значения MCP-серверов (переменные окружения, заголовки) MUST быть скрыты по
  умолчанию и раскрываться только явным действием пользователя для конкретного значения.

**Включение и выключение**

- **FR-011**: Пользователь MUST иметь возможность включать и выключать плагины глобально и для проекта.
- **FR-011a**: Переключение для проекта MUST записываться только в личные настройки: `.claude/settings.local.json`
  проекта, а для MCP-серверов уровня пользователя — в запись этого проекта в личном файле Claude Code
  (`~/.claude.json`), как это делает сам Claude Code. Общий `.claude/settings.json` проекта приложение не изменяет.
- **FR-012**: Пользователь MUST иметь возможность включать и выключать MCP-серверы глобально и для
  проекта, не удаляя их описание из конфигурации.
- **FR-013**: Пользователь MUST иметь возможность включать и выключать свои skills (user и project)
  штатной настройкой `skillOverrides`; skills из плагинов переключателя не имеют (включаются вместе с
  плагином), причина видна в подсказке. Файлы и папки skills приложение не переносит и не переименовывает.
- **FR-014**: Перед каждой записью система MUST сохранять копию изменяемого файла с отметкой времени в
  папке данных Echo Studio (не рядом с файлом) и хранить последние 20 копий на каждый файл.
- **FR-015**: Запись MUST менять только ключ, относящийся к переключателю, сохраняя остальные ключи и
  их порядок; файл MUST перечитываться непосредственно перед записью.
- **FR-016**: Неудачная запись MUST оставлять файл нетронутым, возвращать переключатель в прежнее
  положение и показывать ошибку с причиной.

**Обновление**

- **FR-017**: Система MUST замечать изменения в папках и файлах конфигурации Claude Code и обновлять
  открытые списки без действий пользователя.

**Удаление EchoVault**

- **FR-018**: Система MUST NOT содержать вкладку Memories, диалоги memories, секции EchoVault и
  резервных копий index.db в Settings, счётчик memories и Reindex в статусе.
- **FR-019**: Система MUST NOT читать, создавать или изменять `~/.memory` и не обращаться к серверу
  эмбеддингов.
- **FR-020**: Settings MUST показывать пути, которые читает обзор (папка конфигурации Claude, файл
  пользовательских настроек, папка проектов Conversations), с действием «Show in Explorer», и список
  копий файлов настроек (какой файл, когда) с «Show in Explorer».

### Key Entities

- **Область (Scope)**: Global или проект. У проекта — путь, имя (как в Conversations), доступность на
  диске.
- **Элемент (Item)**: skill, command, agent, plugin или MCP-сервер. Атрибуты: тип, имя (с пространством
  имён плагина, если есть), описание, файл-источник, область, плагин-источник, состояние, ошибка чтения.
- **Плагин (Plugin)**: имя, marketplace, версия, включён ли (глобально / в проекте), состав — какие
  элементы он приносит.
- **MCP-сервер**: имя, способ подключения (локальная команда или адрес), аргументы, скрытые значения
  окружения и заголовков, где объявлен, включён ли для области.
- **Итог проекта (Effective set)**: набор элементов, доступных Claude в проекте, с отметками источника
  и перекрытий.
- **Копия файла (Config backup)**: снимок файла настроек перед записью, с отметкой времени.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На машине пользователя (≈105 skills, 39 agents, 13 commands, плагины, 3 глобальных MCP)
  вкладка показывает полный список Global меньше чем за 1 секунду после открытия.
- **SC-002**: 100 % элементов, которые Claude Code загружает в проекте, присутствуют в итоге этого
  проекта (сверка с тем, что Claude Code показывает в сессии), и ни одного лишнего.
- **SC-003**: Поиск сужает список на каждое нажатие клавиши без заметной задержки (до 100 мс на
  ≈250 элементах).
- **SC-004**: Включение или выключение отражается в интерфейсе меньше чем за 1 секунду; после каждой
  записи есть копия прежнего файла, а сравнение файлов до и после показывает изменение только одного
  ключа.
- **SC-005**: Изменение конфигурации снаружи отражается в открытой вкладке за 2 секунды или быстрее.
- **SC-006**: На машине без EchoVault в интерфейсе нет ни одного упоминания EchoVault или memories, и
  приложение не создаёт `~/.memory`.
- **SC-007**: Один повреждённый файл конфигурации не мешает показать все остальные элементы.

## Assumptions

- Пользователь — один человек на своей машине Windows; Claude Code установлен и настраивается
  стандартными файлами в домашней папке и в проектах.
- Показываются только установленные плагины; каталог marketplace (доступные, но не установленные)
  вне объёма.
- Hooks, output styles, statusline и прочие настройки Claude Code вне объёма; удаление и правка
  файлов skills, commands, agents вне объёма — только просмотр и переключатели.
- Commands и agents — только просмотр: штатного выключателя у Claude Code для них нет.
- Изменения в конфигурации вступают в силу в новых сессиях Claude Code; приложение не управляет
  запущенными сессиями.
- Проверка и запуск MCP-серверов (подключение, список их инструментов) вне объёма.
- Форма каждого экрана и компонента выбирается пользователем на стенде (ROADMAP v0.3.0, «Дизайн —
  стенд на каждый компонент») до реализации; спецификация форму не фиксирует.
- Удаление EchoVault делается первым и не требует миграции данных: у пользователя EchoVault нет.
