# Feature Specification: Рабочее место

**Feature Branch**: `005-workbench`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "Хочу одно окно, где я вижу все свои проекты из C:\Users\stillmvd\Projects деревом с иконками,
по кнопке запускаю Claude и dev-сервер проекта, вижу статус каждой сессии Claude и каждого dev-сервера, удобно
переключаюсь между терминалами, а ещё — дашборд с метриками и понимание, чей процесс висит в диспетчере задач.
VS Code-workspace на 40 корней путает, Claude Desktop ставить не хочу." Решения, выбор стендов 301/302 и правила
пульта — `.planning/WORKBENCH.md` (источник истины по форме).

## Clarifications

### Session 2026-10-20

- Q: Где живёт оболочка? → A: Новый главный раздел Echo Studio («Рабочее место», первый пункт рейла), форма — со стендов 301 и 302 на Kockers DS в стиле Echo Studio.
- Q: Где идут терминалы? → A: Внутри окна. Процессы держит отдельный фоновый хост: закрытие, перезапуск или обновление окна Echo Studio сессии не убивает; хост живёт, пока есть хотя бы одна сессия, и выходит сам, когда закрыта последняя.
- Q: Сколько сессий Claude в одном проекте? → A: Несколько.
- Q: Как видеть несколько проектов сразу? → A: «Пульт» (302 C): общая сетка 1×1 / 2×1 / 2×2; ячейку занимает проект со своими вкладками; ячейки по приоритету занимают ждущие и работающие сессии; булавка держит ячейку; не влезшие — в полосе сессий под меткой «Вне сетки».
- Q: Ctrl+Tab листает что? → A: Все сессии всех проектов, недавние первыми; Shift — назад; отпустил — перешёл.
- Q: Что с пунктом «Открыть в Claude» в проводнике, командой `cc` и сессиями в Windows Terminal? → A: Не трогаем, пока оболочка не проверена в работе; перевод — отдельным шагом по решению пользователя.
- Q: Откуда лимит 5 часов и недели? → A: Из данных, которые Claude Code сам отдаёт статусной строке; приложение в сеть за ними не ходит.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Запустить Claude в проекте и работать прямо в окне (Priority: P1)

Пользователь открывает раздел «Рабочее место», видит дерево своих проектов с иконками папок, выбирает проект и
жмёт «Claude». В окне открывается терминал с Claude Code в папке проекта, и работа идёт как в Windows Terminal:
ввод, Shift+Enter для новой строки, вставка картинки Alt+V, копирование выделенного, прокрутка. Закрыл окно
Echo Studio — Claude продолжает работать; открыл снова — терминал на месте, с тем, что было на экране.

**Why this priority**: это ядро — без него остальное лишь витрина. Сразу убирает хаос из вкладок VS Code.

**Independent Test**: запустить Claude в проекте из дерева, дать задачу, закрыть Echo Studio, дождаться конца
задачи, открыть Echo Studio — сессия жива, вывод на месте, можно продолжать.

**Acceptance Scenarios**:

1. **Given** раздел открыт, **When** пользователь смотрит на дерево, **Then** группы (`Windows Apps`, `Freelance`…) и
   проекты показаны с их иконками папок, внутрь проекта дерево не заходит, служебные папки (`_archived`,
   `_maintenance`, `_build`) скрыты.
2. **Given** выбран проект, **When** пользователь жмёт «Claude», **Then** в течение 2 с открывается вкладка с Claude
   Code в папке проекта, у вкладки — название сессии, как только Claude его даст.
3. **Given** Claude ждёт ввода, **When** пользователь жмёт Shift+Enter, Alt+V (в любой раскладке) или вставляет текст,
   **Then** Claude получает перевод строки, вставку картинки и текст так же, как в Windows Terminal.
4. **Given** идут две сессии, **When** окно Echo Studio закрыто и открыто снова, **Then** обе сессии живы, их экран и
   историю можно листать колесом, работа не прерывалась.
5. **Given** в проекте уже идёт сессия, **When** пользователь жмёт «Claude» ещё раз, **Then** открывается вторая
   независимая сессия рядом, первая не трогается.
6. **Given** Claude в сессии завершился, **When** пользователь смотрит на вкладку, **Then** она помечена завершённой и
   предлагает продолжить эту же сессию одной кнопкой.

### User Story 2 - Видеть, кто чего ждёт, и переключаться (Priority: P1)

В блоке «Запущено» над деревом — все сессии Claude и dev-серверы со статусом: ждёт тебя, работает, готово,
простаивает. На проектах и свёрнутых группах дерева — чипы со статусом. Внизу всегда видна полоса сессий; Ctrl+Tab
переключает на недавнюю сессию любого проекта.

**Why this priority**: при нескольких параллельных проектах главное — не пропустить, где Claude ждёт ответа.

**Independent Test**: запустить три сессии в разных проектах, довести одну до вопроса Claude — она поднимается
первой в «Запущено» и в полосе со значком «ждёт тебя»; Ctrl+Tab открывает предыдущую сессию.

**Acceptance Scenarios**:

1. **Given** Claude в сессии задал вопрос или ждёт разрешения, **When** состояние сменилось, **Then** не позже чем
   через 2 с сессия помечена «ждёт тебя» в «Запущено», в полосе и в дереве, и стоит первой.
2. **Given** группа в дереве свёрнута, а внутри работает сессия, **Then** на строке группы виден чип её статуса.
3. **Given** открыто несколько сессий, **When** пользователь держит Ctrl и жмёт Tab, **Then** появляется список всех
   сессий, недавние первыми; Tab — дальше, Shift+Tab — назад, отпустил Ctrl — переход.
4. **Given** сессия Claude запущена вне оболочки (проводник, `cc`, Windows Terminal), **Then** она видна в «Запущено»
   с пометкой «вне оболочки» и статусом, но без терминала.

### User Story 3 - Dev-сервер проекта по кнопке (Priority: P2)

У проекта с командой запуска (`dev`/`start`, `tauri dev`) в шапке — капсула dev: запустить, остановить, порт,
открыть в браузере. Лог — вкладкой рядом с Claude в той же ячейке.

**Why this priority**: второй по частоте ручной шаг после запуска Claude.

**Independent Test**: в AM 2.0 нажать dev → в течение 10 с капсула показывает порт веба, кнопка открывает адрес,
вкладка лога показывает вывод; «стоп» гасит все процессы сервера, включая дочерние.

**Acceptance Scenarios**:

1. **Given** у проекта есть команда запуска, **When** пользователь жмёт dev, **Then** сервер стартует в фоновом хосте,
   капсула показывает «запускается», затем порт(ы), которые сервер реально слушает.
2. **Given** сервер работает, **When** пользователь жмёт «стоп», **Then** завершается всё дерево процессов сервера
   (vite, node --watch, cargo, exe приложения), порт освобождается.
3. **Given** сервер упал, **Then** капсула помечена ошибкой, лог сохранён, есть «запустить снова».
4. **Given** у проекта нет команды запуска, **Then** кнопки dev нет.

### User Story 4 - Пульт: несколько проектов на одном экране (Priority: P2)

Общая сетка 1×1, 2×1 или 2×2 (три значка раскладки). В ячейке — проект с компактными вкладками-капсулами: его
сессии Claude и лог dev. Ячейки сами занимают ждущие и работающие сессии; булавка держит ячейку; кто не влез —
в полосе снизу под «Вне сетки».

**Why this priority**: «охранник у камер» — видеть сразу, что происходит в нескольких проектах.

**Independent Test**: сетка 2×2, пять живых сессий в пяти проектах, одна переходит в «ждёт тебя» — она занимает
ячейку самой низкоприоритетной незакреплённой, вытесненная уходит в «Вне сетки»; ячейка, где пользователь печатает,
не сдвинулась.

**Acceptance Scenarios**:

1. **Given** раскладка 2×1, **When** пользователь выбирает 2×2, **Then** сетка перестраивается без перезапуска сессий,
   раскладка запоминается.
2. **Given** сессия перешла в «ждёт тебя», **Then** она занимает ячейку по приоритету «ждёт тебя → ошибка → работает →
   готово → простаивает» (внутри группы выше тот, кто дольше ждёт), ячейка отмечена рамкой акцента.
3. **Given** пользователь печатает или прокручивает в ячейке, **Then** эта ячейка не переставляется, пока фокус не уйдёт;
   у полосы сессий виден счётчик «ещё ждут: N».
4. **Given** ячейка закреплена булавкой или проект открыт вручную (дерево, полоса, Ctrl+Tab), **Then** авто-порядок её
   не трогает.
5. **Given** в одной ячейке Claude и лог dev, **When** пользователь жмёт капсулу вкладки, **Then** содержимое ячейки
   переключается, процессы обоих продолжают работать.

### User Story 5 - Продолжить разговор в проекте без сессий (Priority: P2)

У проекта без живых сессий — «Новая сессия Claude», «запустить dev» и список его прошлых conversations: последние
сверху, высота ограничена, прокрутка. Клик продолжает выбранный разговор в оболочке.

**Why this priority**: продолжение прошлой работы — частый старт дня.

**Independent Test**: Booked без сессий → список из 13 conversations, первый — от 19 окт; клик → открывается сессия
с этим разговором.

**Acceptance Scenarios**:

1. **Given** у разговоров нет названия и первые запросы одинаковые, **Then** строки различимы: время и первая строка
   ответа Claude вместо повторяющегося запроса.
2. **Given** разговор уже открыт в другой живой сессии, **When** пользователь кликает его, **Then** оболочка переходит к
   этой сессии, а не запускает второй экземпляр.

---

### User Story 6 - Обзор: расход, git, активность (Priority: P3)

Пункт «Обзор» в дереве: плитки (лимит 5 часов, неделя, токены сегодня, сколько запущено), таблица проектов
(сейчас, токены за 7 дней, git: незакоммиченное, незапушенное).

**Why this priority**: полезно, но без него работа идёт.

**Independent Test**: открыть Обзор — числа токенов по проектам совпадают с подсчётом по транскриптам за 7 дней,
лимит совпадает со статусной строкой Claude.

**Acceptance Scenarios**:

1. **Given** Claude Code сообщил лимиты статусной строке, **Then** плитки показывают проценты и время сброса; если
   данных нет — плитка честно пишет «нет данных», без запроса в сеть.
2. **Given** у проекта есть незакоммиченные файлы или незапушенные коммиты, **Then** в таблице видны счётчики и ветка.

---

### User Story 7 - Чей это процесс и завершить висящее (Priority: P3)

В Обзоре — процессы по проектам: claude, node, dev-серверы, rust-analyzer, MCP-браузеры и MCP-серверы, с памятью.
Висящие (проекта или сессии уже нет, дубль) — первыми, с «Завершить» и «Завершить все».

**Why this priority**: прямо закрывает «висит rust-analyzer, жрёт память, а я не знаю, чей он».

**Independent Test**: закрыть сессию, оставив её MCP-сервер и rust-analyzer → они в «Без проекта» с причиной;
«Завершить все» убирает их, живые сессии не тронуты.

**Acceptance Scenarios**:

1. **Given** процесс запущен из папки проекта или потомком его сессии, **Then** он в группе этого проекта.
2. **Given** процесс принадлежит закрытой сессии или это второй экземпляр того же сервера, **Then** он в «Без проекта»
   с причиной («сессия закрыта 2 ч назад», «второй экземпляр»).
3. **Given** пользователь жмёт «Завершить» у claude.exe живой сессии, **Then** требуется подтверждение; висящие
   процессы завершаются сразу, без подтверждения.
4. **Given** «Завершить все» в «Без проекта», **Then** завершаются только перечисленные там процессы.

### Edge Cases

- Фоновый хост упал или машина перезагрузилась → сессии потеряны; оболочка показывает, какие сессии были открыты, и
  предлагает продолжить каждую (`--resume` по id сессии).
- Две копии Echo Studio → обе подключаются к одному хосту, второй хост не стартует.
- Папка проекта переименована или удалена при живой сессии → сессия работает дальше, в дереве помечена «папки нет».
- Порт dev-сервера занят → капсула показывает ошибку из лога, а не «запущено».
- Проект без иконки в `desktop.ini` → нейтральный значок, без ошибки.
- `desktop.ini`, `package.json`, транскрипт битые → страдает только свой проект или строка (принцип III).
- Очень длинный вывод (сборка) → прокрутка не тормозит окно, буфер ограничен, старые строки отбрасываются.
- Окно уже 1000 px или в сетке 2×2 → вкладки сжимаются с многоточием, имена проектов не наезжают на вкладки.
- Ctrl+C в терминале: есть выделение — копировать, нет — передать в Claude прерывание. Выделение мышью в Claude —
  с Shift (Claude перехватывает мышь).
- Ctrl+Z или двойная «←» на пустом поле уводят attach из сессии (отсоединение, список фоновых сессий) → оболочка
  возвращает ячейку к её сессии.

## Requirements *(mandatory)*

### Дерево и раздел

- **FR-001**: Раздел «Рабочее место» — первый пункт рейла Echo Studio.
- **FR-002**: Дерево строится из `C:\Users\stillmvd\Projects` по тем же правилам, что `_maintenance/sync-workspace.py`:
  папка с маркером (`.git`, `package.json`, `manifest.json`, `index.html`, `CLAUDE.md`, `.gitignore`, `.vscode`) — проект,
  без маркера на верхнем уровне — группа; служебные папки и `node_modules` скрыты; внутрь проекта дерево не заходит.
- **FR-003**: Иконка группы и проекта — из `desktop.ini` папки; дерево обновляется при появлении и удалении папок без
  перезапуска приложения.
- **FR-004**: Строка проекта показывает чипы: сессии Claude (значок самого срочного статуса и число) и dev (порт);
  свёрнутая группа — чипы своих проектов. Длинные имена обрезаются многоточием, полное — в подсказке.
- **FR-005**: Шапка проекта: иконка, имя, путь, чип git (ветка, незакоммиченное, незапушенное), чип профиля
  chrome-devtools MCP (имя профиля, фоновый или видимый), капсула dev, раскладка, «Claude».

### Терминалы и хост

- **FR-010**: Сессии Claude и dev-серверы работают в отдельном фоновом процессе-хосте, а не в процессе окна; окно —
  клиент, который подключается, показывает и отключается.
- **FR-011**: Хост стартует с первой сессией и завершается сам, когда закрыта последняя; одновременно работает не
  больше одного хоста.
- **FR-012**: При подключении окно получает экран каждой сессии целиком (перерисовывает сам Claude), историю разговора
  листает колесо мыши внутри Claude; у dev-лога — не меньше 5 000 последних строк.
- **FR-013**: Терминал передаёт клавиши как Windows Terminal с привязками пользователя: Shift+Enter → перевод строки,
  Alt+V → вставка картинки (в любой раскладке), Ctrl+V → вставка текста, Ctrl+C → копировать при выделении или
  прерывание без него.
- **FR-014**: Claude запускается фоновой сессией Claude Code (`claude --bg`) в папке проекта; продолжение —
  `claude --bg --resume <id>` без других флагов (с флагами Claude создаёт копию). Папка не доверена — оболочка говорит
  об этом и предлагает разовый запуск «Открыть в Claude», доверие сама не ставит.
- **FR-015**: Оболочка знает id сессии Claude каждого своего терминала и связывает его с файлом состояния хука
  `~/.claude/state/sessions/<id>.json`.
- **FR-016**: Название вкладки — название сессии из транскрипта (`custom-title`, `ai-title`), до него — «Claude».

### Статусы и переход

- **FR-020**: Статус сессии — из списка сессий Claude Code (`claude agents --json`: работает, ждёт, простаивает) и
  файлов состояния хука (готово, ошибка, тип работы); «готово» становится «простаивает», когда пользователь посмотрел
  сессию в оболочке; в интерфейсе — сплошной значок по типу работы, как в Taskbar Claude Sessions.
- **FR-021**: «Запущено» — сессии и dev-серверы, отсортированные по срочности; сессии вне оболочки — с пометкой.
- **FR-022**: Полоса сессий внизу всегда видна; не влезшие в сетку — после метки «Вне сетки».
- **FR-023**: Ctrl+Tab / Ctrl+Shift+Tab — список всех сессий, недавние первыми, переход при отпускании Ctrl.

### Пульт

- **FR-030**: Раскладки 1×1, 2×1, 2×2, переключатель — три значка; раскладка и закрепления запоминаются между запусками.
- **FR-031**: Ячейка — проект с вкладками-капсулами (сессии Claude и лог dev) и «+»; в одном проекте может быть
  несколько ячеек.
- **FR-032**: Авто-порядок ячеек по правилам пульта из `.planning/WORKBENCH.md`: приоритет, вытеснение самой
  низкоприоритетной незакреплённой, ячейку под рукой не двигать, булавка и ручное открытие закрепляют.

### Dev-сервер

- **FR-040**: Команда dev определяется по `package.json` (`tauri dev` при `src-tauri`, иначе `dev`, иначе `start`;
  менеджер — по lock-файлу); нет команды — нет кнопки.
- **FR-041**: Капсула показывает состояние (запускается, работает, ошибка) и порты, которые слушают процессы сервера.
- **FR-042**: «Стоп» завершает всё дерево процессов сервера; «открыть» — первый веб-порт в браузере по умолчанию.

### Проект без сессий

- **FR-050**: Кнопки «Новая сессия Claude», «запустить dev» и список conversations проекта (последние сверху,
  ограниченная высота, прокрутка); строки различимы по времени и первой строке ответа.
- **FR-051**: Клик по разговору, уже открытому в живой сессии, переводит к ней.

### Обзор и процессы

- **FR-060**: Плитки: лимит 5 часов и неделя (проценты, сброс) из данных статусной строки Claude Code; токены
  сегодня; число запущенных сессий и dev-серверов.
- **FR-061**: Таблица проектов: значок «сейчас», токены за 7 дней из транскриптов, git (незакоммиченное,
  незапушенное).
- **FR-062**: Процессы claude, node, dev-серверов, rust-analyzer, Chrome MCP-профилей с памятью, по проектам;
  «Без проекта» с причиной — первыми, «Завершить» у строки и «Завершить все».
