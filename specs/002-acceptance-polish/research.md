# Research: Доработки после приёмки v0.3.0

## R1. Почему у превью результата нет нижнего отступа

- **Decision**: заменить `max-h-[3.2em]` у `<pre>` превью в `ToolStepRow` на `line-clamp-2`.
- **Rationale**: `max-h` считает высоту вместе с `py-1.5`: две строки по `leading-normal` = 3em, плюс
  12 px отступов ≈ 4em > 3.2em — нижний отступ и часть второй строки срезаются. `line-clamp` ограничивает
  строки, а отступы остаются целыми.
- **Alternatives**: пересчитать `max-h` в `calc(3em+12px)` — хрупко при смене шрифта.

## R2. Откуда брать вопрос и ответ AskUserQuestion

- **Decision**: вопросы — `use.toolInputJson.questions` (question, header, options[label, description],
  multiSelect); ответ — `result.raw.toolUseResult.answers` (вопрос → строка) и
  `toolUseResult.annotations` (вопрос → { notes }). Если `toolUseResult` нет — разбор текста результата
  `"Q"="A"` регуляркой; не разобралось — исходный текст (FR-011).
- **Rationale**: `DisplayItem.raw` — вся строка JSONL, `toolUseResult` в ней есть (проверено на логах
  машины: ключи `questions`, `answers`, `annotations`). Бэкенд менять не нужно.
- **Множественный выбор**: ответ — выбранные подписи через `", "`. Подписи сами могут содержать запятые,
  поэтому сопоставление жадное: берём варианты, чья подпись совпадает с началом остатка строки; всё, что не
  совпало ни с одной подписью, — свой ответ.
- **Нет ответа**: результат с `is_error` или без `answers` → «No answer».

## R3. Дубликаты со skills плагинов

- **Decision**: в `mark_conflicts` (`effective.rs`) включать в группы имён skills плагинов (ключ — короткое
  `name`); различать источники по паре (origin, pluginKey), а не только по origin, чтобы два плагина с одним
  именем тоже давали `SameName`. MCP и agents плагинов — как сейчас (вне групп).
- **Счётчик «N duplicates»**: число элементов с `conflict === 'sameName'` в показанной области. Перекрытия
  MCP/agents уже видны чипом «override» и вложенными строками — их не дублируем.

## R4. Группы skills в виртуализированном списке

- **Decision**: `groupSkills(items)` в `src/lib/tooling.ts` превращает список в строки двух видов:
  `{type:'group', key, title, count, open}` и `{type:'item', item, depth}`. Виртуализатор получает
  плоский массив строк; размер строки зависит от вида. Ключ группы: `plugin:<pluginKey>` или
  `prefix:<prefix>`.
- **Состояние**: `toolsOpenGroups: string[]` в ui-store (persist) — раскрытые ключи; по умолчанию группы
  свёрнуты (или по выбору стенда). При непустом поиске группы с совпадениями считаются раскрытыми.
- **Alternatives**: вложенный список без виртуализации — нарушает принцип IV на 130+ skills.

## R5. Missing-проекты и сессии

- **Decision**: `ScopePanel` делит проекты на `available` и missing; missing — в конце, в группе с
  локальным состоянием «раскрыта» (по умолчанию закрыта, открыта, если выбран её проект). Число сессий —
  из `useConversationProjects()` (тот же запрос, что в Conversations), сопоставление по нормализованному
  пути (`cwd` ↔ `scope.path`: регистр, `\`/`/`, хвостовой слэш). «Open in Conversations» —
  `setConversationsProjectId(id)` + `setActiveTab('conversations')`.
- **Alternatives**: считать сессии в Rust при `list_tool_scopes` — лишний скан, данные уже есть на фронте.

## R6. Стенды

- Стенд 5 — группы skills: заголовок группы (вид, счётчик, шеврон), состояние по умолчанию (всё свёрнуто /
  раскрыто), отступ вложенных строк, группа из плагина vs префикса. Киоск на реальных skills машины.
- Стенд 6 — карточка вопроса: список вопросов, отметка выбора (чип / радио / подсветка), свой ответ,
  множественный выбор, «No answer», заметки. Киоск на реальных вопросах из логов.
- Missing-группа и экран missing-проекта — из готовых частей (заголовок «Projects · N», CenterNote), без
  стенда (память: стенды только для новых компонентов).
