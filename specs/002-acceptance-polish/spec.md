# Feature Specification: Доработки после приёмки v0.3.0

**Feature Branch**: `002-acceptance-polish`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "v0.3.1 — доработки после приёмки v0.3.0. 1) Conversations viewer: блок результата инструмента — нижний отступ равен верхнему. 2) Conversations viewer: AskUserQuestion как вопрос/ответ, форма через стенд. 3) Tools, All scopes: missing-проекты в свёрнутую группу внизу, справа путь, число сессий и «Open in Conversations». 4) Tools, skills: группировка по вендору (плагин; префикс до «-» при ≥3), сворачивание, форма через стенд. 5) Дубликаты: учитывать skills плагинов, чип «N duplicates» с фильтром."

## Clarifications

### Session 2026-09-26

- Q: Что делать с проектами, чьей папки больше нет? → A: Свернуть в группу «Missing · N» в конце списка
  областей; при выборе — путь, число сессий и переход в Conversations. Запись проекта в конфиге не трогается.
- Q: По какому правилу собирать skills в группы? → A: Skills плагина — группа по плагину; остальные — по
  префиксу имени до первого «-», если у префикса не меньше 3 skills; одиночки без группы.
- Q: Как решить форму карточки вопроса/ответа и групп skills? → A: Стендом вариантов, как для прочих новых
  компонентов.
- Q: Расширять ли подсветку дубликатов? → A: Да: учитывать skills плагинов и показать сводку «N duplicates»
  в шапке списка с фильтром по клику.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Skills собраны по вендору (Priority: P1)

В области 133 skills, из них десятки одного набора (`gsd-*`, `speckit-*`, skills плагина). Пользователь
открывает тип Skills и видит наборы свёрнутыми группами с названием и числом, а одиночные skills —
обычными строками. Группу можно раскрыть и свернуть.

**Why this priority**: длинный плоский список — главная жалоба при приёмке; группы сокращают его в разы.

**Independent Test**: открыть Global → Skills; все skills с префиксом `gsd-` находятся в одной группе
«gsd» с верным числом; skills плагина chisle — в группе «chisle»; `better-ui` без группы, если у префикса
«better» меньше 3 skills.

**Acceptance Scenarios**:

1. **Given** в области есть 3 и более skills с общим префиксом до первого «-», **When** пользователь
   выбирает тип Skills, **Then** они показаны одной группой с названием префикса и числом элементов.
2. **Given** skills из плагина, **When** выбран тип Skills, **Then** они собраны в группу с именем плагина,
   независимо от префиксов их имён.
3. **Given** группа, **When** пользователь нажимает на её заголовок, **Then** она раскрывается или
   сворачивается; состояние сохраняется при переключении областей и перезапуске.
4. **Given** введён поиск, **When** совпадения есть внутри свёрнутой группы, **Then** группа показывает
   совпадения без ручного раскрытия.
5. **Given** элемент внутри группы выключен или перекрыт, **When** группа раскрыта, **Then** строка
   выглядит так же, как вне группы (тусклая, с чипами и переключателем).

### User Story 2 - Дубликаты видны сразу (Priority: P2)

Пользователь хочет знать, не лежит ли один и тот же skill дважды — в своей папке и в плагине, или
глобально и в проекте. В шапке списка видна сводка «N duplicates»; клик оставляет в списке только
дубликаты, повторный клик снимает фильтр.

**Why this priority**: дубликаты путают Claude и пользователя, но случаются реже, чем длинный список.

**Independent Test**: создать skill с тем же коротким именем, что у skill плагина; оба помечены
«same name», счётчик в шапке вырос на 2, фильтр по клику показывает их двоих.

**Acceptance Scenarios**:

1. **Given** skill пользователя или проекта и skill плагина с одинаковым коротким именем, **When** открыта
   область, **Then** оба помечены «same name».
2. **Given** в области есть дубликаты, **When** пользователь смотрит на шапку, **Then** видит чип
   «N duplicates», где N — число помеченных элементов.
3. **Given** чип, **When** пользователь нажимает на него, **Then** в списке остаются только помеченные
   элементы; повторный клик возвращает полный список.
4. **Given** дубликатов нет, **When** открыта область, **Then** чипа нет.

### User Story 3 - Пропавшие проекты не мешают (Priority: P2)

В списке областей десятки проектов, у части папка удалена («missing»). Они уходят в конец, в свёрнутую
группу «Missing · N». Выбрав такой проект, пользователь видит путь, сколько у него сессий и может перейти
к ним в Conversations, чтобы посмотреть или удалить.

**Why this priority**: сейчас missing-проекты перемешаны с живыми и выбор ничего не даёт.

**Independent Test**: при наличии проектов без папки — живые идут первыми, missing собраны в свёрнутую
группу с верным числом; выбор missing-проекта показывает путь и число сессий, «Open in Conversations»
открывает этот проект во вкладке Conversations.

**Acceptance Scenarios**:

1. **Given** есть проекты без папки, **When** открыта вкладка Tools, **Then** они собраны в свёрнутую
   группу «Missing · N» после всех живых проектов.
2. **Given** группа, **When** пользователь раскрывает её и выбирает проект, **Then** справа видит путь,
   число сессий и «Open in Conversations».
3. **Given** у missing-проекта есть сессии, **When** пользователь нажимает «Open in Conversations»,
   **Then** открывается вкладка Conversations с выбранным этим проектом.
4. **Given** у missing-проекта нет сессий, **When** он выбран, **Then** показано «No sessions», перехода нет.
5. **Given** missing-проект был выбран до перезапуска, **When** приложение открывается снова, **Then**
   группа раскрыта, проект выделен.

### User Story 4 - Вопросы ассистента и мои ответы в сессии (Priority: P2)

В ленте сессии вызов инструмента-вопроса сейчас показан как сырая строка аргументов и текст результата.
Пользователь видит вместо этого карточку: каждый вопрос, предложенные варианты и какой выбран — в том
числе свой ответ, введённый вместо вариантов, и несколько выбранных при множественном выборе.

**Why this priority**: решения, принятые в диалоге, важны при перечитывании сессии, а в сыром виде их
трудно найти.

**Independent Test**: открыть сессию, где ассистент задавал вопросы с вариантами; карточка показывает все
вопросы, отмечен выбранный вариант, свой ответ показан текстом; сессия с отклонённым вопросом показывает
вопросы с пометкой «No answer».

**Acceptance Scenarios**:

1. **Given** в сессии есть вызов вопроса с ответом, **When** пользователь открывает сессию, **Then** видит
   карточку со всеми вопросами, их вариантами и отмеченным выбором.
2. **Given** пользователь ответил своим текстом, **When** карточка показана, **Then** его текст виден как
   ответ, варианты не отмечены.
3. **Given** вопрос с множественным выбором, **When** карточка показана, **Then** отмечены все выбранные
   варианты.
4. **Given** ответа нет (отклонён, прерван), **When** карточка показана, **Then** вопросы видны с пометкой
   «No answer».
5. **Given** экспорт сессии в markdown, **When** в ней есть вопросы, **Then** они выгружаются как
   «вопрос → ответ».

---

### User Story 5 - Ровные блоки результата (Priority: P3)

В ленте сессии блок результата инструмента с одной-двумя строками прижат к нижнему краю: нижний отступ
меньше верхнего. Пользователь видит блок с равными отступами.

**Why this priority**: косметика, но заметна на каждом экране ленты.

**Independent Test**: открыть сессию с результатами в одну, две и много строк; отступ снизу равен отступу
сверху во всех случаях.

**Acceptance Scenarios**:

1. **Given** результат из одной или двух строк, **When** он показан, **Then** отступ от текста до нижнего
   края блока равен отступу до верхнего.
2. **Given** длинный результат, свёрнутый до нескольких строк, **When** он показан, **Then** отступы те же.

---

### Edge Cases

- Префикс совпадает с полным именем skill (`gsd` и `gsd-next`) — skill `gsd` входит в группу «gsd».
- Skill плагина с префиксом, который есть и у пользовательских (`gsd-x` из плагина) — остаётся в группе
  плагина; пользовательские считаются отдельно.
- После выключения элемента или поиска в группе не осталось строк — группа не показывается.
- Одинаковое короткое имя у двух skills одного плагина не бывает; одинаковое у skills двух разных
  плагинов — тоже «same name».
- Проект стал missing или вернулся, пока приложение открыто — группа пересчитывается при обновлении
  списка областей.
- Вопрос без вариантов (только свободный ввод) — карточка показывает вопрос и текст ответа.
- Текст ответа невозможно разобрать — карточка показывает вопросы и исходный текст результата.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: При типе Skills список MUST собирать skills плагина в группу по имени плагина.
- **FR-002**: Остальные skills MUST собираться в группу по префиксу имени до первого «-», если у префикса
  не меньше 3 skills в показанном списке; иначе skill показывается без группы.
- **FR-003**: Группа MUST показывать название и число элементов и раскрываться/сворачиваться по клику;
  состояние групп MUST сохраняться между областями и перезапусками.
- **FR-004**: При активном поиске группы с совпадениями MUST показывать совпадения без ручного раскрытия.
- **FR-005**: Skill пользователя или проекта и skill плагина с одинаковым коротким именем MUST помечаться
  «same name»; то же для skills разных плагинов.
- **FR-006**: Шапка списка MUST показывать чип «N duplicates», когда в области есть помеченные элементы;
  клик MUST включать и выключать фильтр «только дубликаты».
- **FR-007**: Проекты без папки MUST показываться после живых, в группе «Missing · N», свёрнутой по
  умолчанию и раскрытой, если выбран один из её проектов.
- **FR-008**: Выбранный missing-проект MUST показывать путь, число сессий и переход «Open in
  Conversations» (при числе сессий больше 0), который открывает этот проект в Conversations.
- **FR-009**: Приложение MUST NOT менять конфиг Claude Code из-за missing-проектов.
- **FR-010**: Вызов инструмента-вопроса в ленте MUST показываться карточкой: вопросы, варианты, выбор;
  свой ответ — текстом; множественный выбор — все выбранные; без ответа — «No answer».
- **FR-011**: Если ответ не разобран, карточка MUST показывать вопросы и исходный текст результата.
- **FR-012**: Экспорт сессии в markdown MUST выгружать вопросы как пары «вопрос → ответ».
- **FR-013**: Блок результата инструмента MUST иметь равные отступы сверху и снизу при любом числе строк.
- **FR-014**: Форма группы skills и карточки вопроса MUST выбираться на стенде до реализации.

### Key Entities

- **Группа skills**: ключ (имя плагина или префикс), название, элементы, раскрыта ли.
- **Missing-проект**: путь, число сессий, ссылка на проект в Conversations.
- **Вопрос ассистента**: заголовок, текст вопроса, варианты (подпись, описание), множественный ли выбор;
  ответ — выбранные варианты или свой текст, либо отсутствие ответа.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В Global → Skills на машине пользователя число строк верхнего уровня при свёрнутых группах
  меньше числа skills минимум в 2 раза.
- **SC-002**: Каждый skill с коротким именем, встречающимся больше одного раза в области, помечен; число
  в чипе совпадает с числом строк под фильтром.
- **SC-003**: Все живые проекты стоят выше любого missing-проекта; число в заголовке группы совпадает с
  числом missing-проектов.
- **SC-004**: В сессии с вопросами ассистента пользователь находит, что он ответил на каждый вопрос, не
  раскрывая сырой текст.
- **SC-005**: У блоков результата в 1, 2 и 20+ строк разница нижнего и верхнего отступа не больше 1 px.

## Assumptions

- Группировка действует только при типе Skills; в «All» и остальных типах список остаётся плоским.
- Порядок: группы и одиночные skills сортируются вместе по названию; внутри группы — как сейчас.
- «Короткое имя» skill плагина — часть после «плагин:»; сравнение без учёта регистра.
- Число сессий missing-проекта берётся из тех же логов, что и в Conversations; проект, известный только из
  конфига, имеет 0 сессий.
- Данные вопроса и ответа уже есть в логе сессии; ничего не читается из внешних источников.
- Выключение целой группы одним действием — вне объёма.
