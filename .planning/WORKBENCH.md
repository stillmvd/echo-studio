# Рабочее место — оболочка для работы над проектами (решения 2026-10-20)

Главный раздел Echo Studio: дерево проектов, терминалы Claude и dev-серверов внутри окна, статусы, дашборд. Дизайн — своим стендом (`/redesign-stand`) на Kockers DS, в стиле Echo Studio.

## Зачем

Сейчас сессии и dev-серверы разбросаны: пункт «Открыть в Claude» в проводнике, `cc`, WT-вкладки, VS Code-workspace на 40 корней, Windhawk-мод и расширение Claude Session Focus. Целой картины нет нигде → путаница, какой терминал чей, забытые процессы.

## Решения

- **Терминалы внутри окна, хост — демон Claude Code** (пересмотрено в плане 2026-10-20, `specs/005-workbench/research.md` R-01). Сессии — фоновые сессии Claude Code (`claude --bg --session-id`), в окне — xterm.js + PTY с `claude attach`; закрытие/обновление окна сессии не убивает. Свой хост ConPTY не пишем. Dev-серверы — отдельные процессы в именованном Job Object, лог в файл (R-04).
- **Дерево проектов** — `C:\Users\stillmvd\Projects`, иконки папок из `desktop.ini`. Проект = папка с маркером, как в `_maintenance/sync-workspace.py` (`.git`, `package.json`, `manifest.json`, `index.html`, `CLAUDE.md`, `.gitignore`, `.vscode`); внутрь проекта дерево не заходит. `_archived`, `_build`, `_maintenance` — скрыть.
- **Claude в проекте** — кнопка на проекте, сессия в терминале хоста; Shift+Enter → `\e\r`, Alt+V → `\ev` (как привязки WT). Статус — из `~/.claude/state/sessions/*.json` (хук `session-status.js`); сессия, запущенная хостом, знает свой pid без поиска по цепочке процессов.
- **Dev-сервер** — команда из `scripts.dev`/`start` (`tauri dev` для Tauri); статус «процесс жив + порт слушает», открыть в браузере, лог отдельной вкладкой.
- **MCP-браузер** — профиль chrome-devtools из `.mcp.json` проекта, видимость (headless или нет).
- **Дашборд**: лимит и токены (из `.jsonl`), активность по проектам, git-состояние всех проектов (незакоммиченное/незапушенное/ветка), ресурсы процессов с привязкой к проекту — claude, node, dev-серверы, rust-analyzer, MCP-Chrome; кнопка «завершить» для зависших. Привязка процесса к проекту — по cwd и цепочке родителей.
- **Старые запуски** (проводник, `cc`, WT) переводятся на оболочку только после того, как она проверена в работе. До этого внешние WT-сессии показываются по файлам состояния.
- **Телеметрия CLI** выключена: `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` в `~/.claude/settings.json`.

- В одном проекте может быть **несколько сессий Claude** одновременно.

## Наблюдения

- У многих conversations нет `ai-title`, и первый запрос одинаковый («Продолжаем Booked.» ×4 у Booked) — в списке «Продолжить» их не различить. Для реализации: показывать дату и время, а вместо первого запроса — первую строку ответа или `custom-title`.

### Правила пульта (302 C, 2026-10-20)

- Приоритет ячеек: ждёт тебя (вопрос, подтверждение) → ошибка → работает → готово → простаивает; внутри группы выше тот, кто дольше ждёт.
- Новая ждущая сессия занимает ячейку самой низкоприоритетной незакреплённой; вытесненная уходит в «Вне сетки» полосы сессий.
- Не двигать под рукой: ячейку, где фокус ввода или прокрутка в последние секунды, не трогать; перестановка ждёт ухода фокуса, до тех пор у полосы — счётчик «ещё ждут: N».
- Булавка держит ячейку; проект, открытый вручную (из дерева, полосы, Ctrl+Tab), закрепляется сам.
